# 小幽灵 · 会唱歌的精灵

一个单页的三维展示页面：一位飘在房间中央的精灵，音乐响起时她会唱。整个场景由代码程序化生成
（没有模型文件、没有贴图文件、没有网络请求），支持鼠标旋转 / 缩放、点她打招呼、
把光标停在她身上她会看过来，并带有一组可以点的动作。

界面做成一张**美术馆展签**：页头是藏品名，右侧是当前条目的正文，底部是控制台。
三套光环境是三个展厅——晴室、夜巢、深潭——直角、无圆角、留白宽。
右侧那张纸是**上下两块**（2026-10-04 之前是左右两半）：上面是**一页人物介绍**，
下面是**互动区**——五个可以让她做的动作，排成一行五格，**一格一击**，点下去就做。
**动作只是姿态，镜头不动**：原来每个动作还带一个为它选好的机位，2026-10-02 拆了，
见「做一次动作会做什么」。

**这一版是换脸。** 最初那台磁带连同它的拆解、翻面与外壳一起**收起来了，
没有删掉**：模型仍然每帧在算，只是 `cas.root.visible = false`（见 `src/main.js` 顶部的
`TAPE_ON`），因为精灵要待在它原来待着的位置上。真正的音乐链路——合成、装带、滑轨、
计数器、循环——一字节没动，见下面「音乐」。

所以这份 README 里凡是在讲**渲染机器**的章节（画面 / 灯光 / AO / 环境光遮蔽 / 设置）
都还是逐字有效的：它们描述的是这台机器，而机器没有换。讲**那台磁带本身**的两节
（材质 / 水墨）也留着，但前面加了牌子——它们讲的东西现在不在画面上。所有"她"的说法
都是从原来说那台磁带的地方改过来的。详细的清单在「换脸」那一节。

**而她本人换过好几版。** 从一开始算起：先是 2D 剪纸的**灵宝**，再换成实体的**纳西妲**
——第一版是"白裙 + 三叶叶冠 + 叶翅"，一个说得通的读法，但是错的读法；随后按参考重做成
**制服**（白短袖衬衫、绿条纹领带、绿格百褶裙、高侧马尾、尖耳朵）。
**这一版是小幽灵**：深紫女巫帽（金带 + 檐底猩红）、白床单（体内青蓝自发光）、一大一小两只眼、
橙红腮红、单弧微笑、红柄扫帚；参考是 B 站 `BV1xRho6DEG4` 的成品渲染，模型在 `src/ghost.js`。
她**没有手脚**，所以五个动作全部由整体姿态表达——沉、晃、转、弹、脱帽。
「她是一个模型，不是一张图」这一节讲的就是这件事，配色见 `src/ghost.js` 顶部的 `C`。
（换脸时它跟着模型搬过家，原来在 `src/nahida.js` 里，那个文件已删。）

**运行时零外部资产。** 她、那间八角石厅、烛台、纹理、环境光，连出厂那两面音乐都是代码生成的
—— 运行时不请求任何模型、贴图或音频文件，产物是一个 1857 KB 的 HTML，双击就开。
（`assets/` 里还留着 2D 时代的两张历史图，已无人引用，见「结构」。）

第三方依赖只有 `three` 与 `esbuild`，都是公开库的常规引用。

## 她是一个模型，不是一张图

**最初她是一张图**：`assets/spirit-cut.webp` 挂在一个永远面向镜头的 `THREE.Sprite` 上
（`src/spirit.js`，那个模块已经删掉）。现在她整个是 **`src/ghost.js`：用图元搭出来的实体**
（中途叫 `src/nahida.js`，那个模块 2026-10-02 也删了 —— 下面凡是提到它的地方，讲的都是历史），
零外部资产——每个面都是 `SphereGeometry` / `LatheGeometry` / `Shape`，**五官也全是网格**：
眼睛是压扁的球、高光是更小的球、腮红是压扁的球、嘴是一个 `TorusGeometry` 弧转成 ∪。
整份 `ghost.js` 里只剩**一张 canvas**：`glowMap()`，一张 8×256 的竖向渐变当体内青光的 `emissiveMap`
（从前的脸是画在 canvas 上、再贴成球面补丁的，那一套随制服版一起删了，见「嘴为什么看不见」）。
所以"唱歌"不再是从剪影上读出来的：她的嘴会张、身体会浮沉、眼睛会眨。
**待机与演唱的差别先落在幅度上**，而不是换成另一套动画；2026-10-03 起还多了一层：
唱起来之后她会**自己挑动作做**——`ghost.js` 里有一本 `SONGBOOK`
（`sway → bounce → reach → sway → swoop → float → sway → bounce`，八个一乐句，走完回到第一个），
对应 `SING` 表里五条**演唱专属**曲线（`sway` 侧倾 / `bounce` 双弹 / `reach` 掀帽 /
`swoop` 前倾 / `float` 升起），每条主打一个通道。
**时机挂在歌曲钟上，不挂页面钟**：`main.js` 把 `audioEl.currentTime` 当 `pos` 传进来，
`floor(pos / 4.5)` 变一次就是一个乐句边界，手势只在边界上起；第一个只等 `SING_FIRST = 1.40`，
两次之间的下限是 `SING_GAP = [2.40, 3.40]`，没有音源时整条退回 `dt`。触发与冷却**走同一个钟**
（`dpos`，歌曲钟这一帧走了多少）——曾经分开挂过，帧率一低两者就分家。
手势带 `st.act.auto = true`，于是 `dance` 那层舞从"满幅或熄火"改成三段：访客点的动作压到 `0`、
她自己的手势压到 `SING_DUCK = 0.34`（让一半），静息回到 `1`。

### 比例就是风格，先把它定死

最早的 3D 那一版（叶裙）头占了全身的 46%（2.76 头身），读成一个不倒翁，制服版把它定在 3 头身。
这一版没有"头身比"这回事——**她的长度单位是「帽檐宽 = 1」**，全场最稳的一把尺子：
帽檐左右两个尖是画面里最外侧的极值点，不受姿态影响。`src/ghost.js` 顶上把这一条当成
第一件事写下来，其余每个数字都是它的倍数：

```
全身高（下摆底 -> 帽冠最高点）  0.812   身体高 0.565   身体宽 0.771
帽冠最高点高出檐面              0.283   帽高（冠顶 -> 檐底）0.446
檐的竖直跨度 0.336   檐宽 1.0   檐倾角 17.1°
脸：眼在身体高的 0.70（左眼是竖椭圆、右眼是更大的圆 —— 这个不对称是原模型就有的，
不是误差）；腮红在 0.57 处；嘴在 0.63 处
```

这些数全是**逐轴**量出来的（`measure9.py` / `measure10.py` 在参考的成品彩色渲染上
逐行逐列扫边缘，而不是拿外框比）。换算成页面尺度：`NOMINAL = 6.38` 是她占的高度包络，
和旧版帽尖到顶一样高；`FLOAT = HEM = 0.80` 是她**飘着**的高度（下摆离地 0.80，
所以是"悬空"不是"站在地板上"）；`B = (NOMINAL − FLOAT) / 1.382 ≈ 4.04`。
全身 **6.38 而不是 6.40**——下摆底下那一截是留白，不是她。

### 这一版的几何：五条约束

上一版那三条（绕序、发丝切线、裙摆半径）里，绕序留了下来（下面第 2 条），另外两条跟着
头发和裙子一起走了。这一版补上的几条都是"看着不对、调参数没用"那一类，
共同点是**问题不在参数上，在坐标系上**：

1. **曲线扫掠是 `sweep(curve, radiusAt, segs, rings)`：`CatmullRomCurve3` 取等距点、
   `computeFrenetFrames` 取每一点的 `(N, B, T)`、逐环铺一个圆截面、端部封真半球帽。**
   圆截面是这一版的**选择**，因为 `computeFrenetFrames` 的"滚转"是它自己挑的——
   实测同一批发束里中缝那束差 90°、外侧那些差 62°–77°，**而且每束各不相同**。
   椭圆截面一上来就要求你知道"哪一边是外侧"，圆截面把这个要求消掉了。
   上一版的发束是椭圆的（`deep` 径向厚、`flat` 横向宽，两个半轴都要给），
   刘海就是信了默认帧、两个轴互换，一束头发渲染成一排竖鳍。
2. **自己写 normal 的网格，绕序也得自己写对。** `grid` 的 `(a, b, c, b, d, c)` 配
   `u` 沿 +θ、`v` 沿 +y 的切向，算出来正好朝外；反过来写就是**全朝内**，外表面被背面剔除，
   渲染出来的是管子内壁——而它看起来像"打光不对"，不像绕序错。这条写在 `grid` 顶上，
   因为它栽过（`nahida.js` 的 `lock`）。
3. **"尖"要加在半径上，不是加在高度上。** 帽檐不是正圆，是**左右两个尖、前后收进去**。
   上一版把那个 `−cos(2θ)` 加在 **y** 上（两侧抬起、前面压低），于是"尖"从来没做出来过，
   做出来的是一个前低后高的碗。这一版挪到半径上（`brimFn`）：θ=±90° 是 +1 顶出去。
   同一条还有一半：**檐底的偏移不是常数**——参考上檐子是"边缘更厚"的一片，不是一张纸，
   给常数 0.013 B 的话檐口只剩一根红线。
4. **`u` 是环向参数，不是"脸宽度的百分比"。** `bodyPoint(u, v)` 里 `θ = u·TAU`、
   `x = sinθ·r`、`z = cosθ·r`，所以**正前方是 u = 0（或 1）**，u = 0.25 是身体的**正右侧**。
   第一版把眼睛写在 0.185 / 0.318、嘴写在 0.25，等于把五官贴到右半边和正右侧——
   正面渲染出来是一张没有脸的白布。正解是从"离中轴多远"反解：脸在 v ≈ 0.69 处半径 0.345 B，
   眼睛要落在 x = ±0.14 B → `asin(0.14 / 0.345)` = 24° → u = 0.067。
5. **身体不是 `B` 高。** 参考上"檐面到下摆底"只有檐宽的 0.563，而宽度方向的身体宽是 0.771
   ——身体比"宽高比 = 1"要**矮**一截。第一版让 v 直接从 `HEM` 走到 `HEM + B`，
   于是身体比参考高了 15%，并排一看就是个直立的坛子。所以有 `BH = 0.875 * B` 这个数。

还有几条更小、但同样是"不写对就白干"的：

- **下摆的波浪是 8 瓣，而且垂坠要小。** 4 个瓣一圈只有 2 个朝前，读成"裙子破了两个洞"；
  奇数在环向接不上。而"最宽那一行"到"最深那一行"只差 0.115 个身体高——垂坠给大了，
  加上剖面自己的抬升，整个身体就会高 15%。
- **竖褶是读法问题，不是比例问题。** 比值全对的时候，我的身体仍然读成一个橡皮枕头、
  参考读成一块布——差别就在这些细褶上（`PLEAT` 16 条，取 8 的整数倍，褶和瓣不打拍子）。
- **凹槽/分界靠"底下那层更暗"才看得见。** `C` 里那档 `bodyDeep`（下摆内侧与背面）是承重的：
  下摆的波浪边就是靠它读出来的，抹平它，边就没了。
- **`glowMap` 的渐变必须烘进 RGB，不能靠 alpha。** `emissiveMap` 在着色器里只取 `.rgb`，
  alpha 从头到尾没被读过：画一张 `rgba(…, 0.16)` 的透明渐变，取回来的 rgb 仍是
  `(150,235,242)`，整件衣服被均匀点亮，渐变等于没画。写成**黑到青再回黑**才是真的
  "胸口亮、下摆暗"。
- **高光要落在"眼球的表面"上。** 眼球是沿法线压扁的（`scale.set(rx, ry, 0.30·rx)`），
  所以先沿法线推 `0.30·rx + 0.012B`，再在切平面里往左上偏 `0.020B`。
- **`face.rotation.y` 的枢轴必须在头的中心**，不在脚下——枢轴留在原点的话，"转脸看光标"
  会变成"把整张脸横着推出去"。

**参考值要先问一句：这是姿态量还是形状量。** 手臂那一处量错过两回，两回都是拿转体帧的
外框当形状：参考那一帧的幽灵转着身子，臂尖被 `cos(yaw)` 缩短，于是 `ARM` 一度被压到
0.505 B（比真值小四倍）。正视图（`clay-front-tight.png`）上臂尖是 0.752 檐宽，
现在取 `ARM = 0.618 B`。同一件事还有一层：`PROFILE` 在 v≈0.74–0.79 的那个鼓包
**也是同一只手臂**——"剖面里的鼓包"和"这里叠的尖"是同一件事量了两遍，相加才是那条剪影。

**最后一道关是叠影，不是比值。** 把参考的剪影和我的剪影都按檐宽归一、按左檐尖对齐
（`_ref/ghost/overlay.py`），红 = 参考多出来的、蓝 = 我多出来的。比值可以全对而形状仍然不对
（"宽下摆"和"宽肩膀"可以是同一个总宽），叠影则直接把差在哪儿、差多少画出来——
帽冠第一版就是这样发现矮了 28% 的：比值只显示 `crown cone h` 0.224 对 0.283，
看不出它矮成了一顶圆帽。

### 上一版（制服）的几何教训

下面这三处是**制服版**做错、小幽灵这一版不再遇到的事。留着是因为错法各不相同，
而每一种错法在这个仓库里都还会再犯：

1. **`LatheGeometry` 的点要从下往上给。** 绕序决定法线朝向：从上往下给点，面朝内、被背面剔除，
   **裙子整个不渲染**——画面上只剩绕裙一圈的叶子（叶子是 `DoubleSide`，所以只有它看得见）。
2. **发丝要挂在它所在球面的切线上**（`strand()`），而且**弯曲量要按它躺的那条弧的矢高算**。
   这一条修了三轮，每轮的病都不一样，值得整条记住：
   - 第一版刘海基点半径 `HEAD_R * 0.80` 小于头半径，整排刘海埋进头里，头就是一个白球。
   - 第二版把基点挪到球面上（`R * 0.99`）——**还是埋着**。因为 `droop` 是"朝正下方转"，
     而在靠近头顶的铰点上，"正下方"和"朝球心"是同一个方向；只有切线才是贴着球面走的那条线。
     实测：把 `hairDark` 临时染成洋红，整排刘海**只有发际线上的一小片露出来**——那片露出来的
     读起来像头发上的脏点，是当时画面里最刺眼的东西。
   - 第三版把姿态改成**显式基向量**（`makeBasis(side, growth, out)`）。之前用
     `setFromUnitVectors` 只规定"生长方向"，**绕轴的滚转是它自己挑的**，而 `leafMesh` 是沿叶片
     自己的 -Z 弯的——于是每根发丝弯向随机一侧，弯向内侧的那些就沉进头里再也出不来。
     基向量把"外侧"也说出来之后，-Z 就一定是朝球心，叶片必定贴着颅骨走。
   - 弯曲量则用**精确矢高** `R(1 − cos(len / 2R))`，不是小角度近似 `len² / 2R`。后者只在
     `len << R` 时成立；`len = 1.90`、`R = 1.06` 时它要求 1.70 的弯曲量，等于把叶片卷过头心
     ——贴脸的两绺长发就是这么整条消失的（拿绿色材质试出来的）。
   - **但矢高只对了量级，形状还是错的**（第四轮才发现，也是这条链上最难的一处）。
     `leafMesh` 的弯曲是一条**抛物线** `z = −c·y²/len`，端点的斜率是 `2c`；而躺在球面上的
     发丝在端点要转过 `L/R` 弧度，斜率是 `tan(L/R)`。两者相等要求 `c = tan(L/R)/2`——
     在 `L ≈ R` 时那是矢高法给的值（0.119）的**六倍**。也就是说发丝从发际线出发时是切向的，
     然后就**再也没转**：它笔直地朝脸前方飞出去，从正面看被压缩成发际线上的一排短条纹，
     而额头**下面**空着——症状是"刘海只贴在头顶上，脸上一大片光额头"，而任何一次只调长度
     或调 `droop` 的尝试都只是让那排条纹长一点。
     正解是把弯曲换成**真的圆弧**：`z = −(R − √(R² − y²))`，并且把 y 按弦长
     `R·sin(len/R)` 缩放，让"长度"量的是**沿颅骨的弧长**而不是直线距离。
     换成弧之后，一根长度 `L`、铰点在极角 `p` 的发丝必定落在 `p + L/R`——
     **刘海的位置从此可以算，不用试**：铰点在离头顶 25.2°，十一根的长度选在 0.88–1.10，
     于是它们的发梢落在 71.7°–87.6°，而眼睛的上沿在 88°。
3. **裙摆半径决定手臂看不看得见。** 第一版裙摆 r = 1.58 而手臂在 r = 0.74，两条胳膊
   整个在裙子里面。收窄到 1.06（`pleatedSkirt` 的 `rBot`）之后手才露出来。
   制服版把三层叶边换成**一条百褶裙**，褶子是半径上的一道**三角波**，而脆度来自材质上的
   `flatShading`——三角波配上平均过的法线是**扇贝边**，扇贝边不是百褶。

还有两处是"管子与叶子"的通病，也各有一条规矩：
- 马尾是 `taperTube`（自己按曲线算逐段半径的管子）。`TubeGeometry` 只有一个半径，
  第一版用它加一串递减小球——一根等粗的绳子，而头发没有等粗的。
- **凡是挂在头上的东西，位置必须是"球面上的点"，不是"看着差不多的坐标"。**
  马尾的铰点写在 `(0.58, 0.46, −0.30) × HAIR_R`，它离头心 0.80 而头发半径是 1.01——
  马尾最粗的那三分之一整个埋在头发里，除了正对镜头以外任何角度都看不见；
  麻花辫同理，五个控制点里有四个在半径 0.82–1.02 之间，只有最后一小截露在外面。
  修法是**把方向归一化再乘半径**，两个都改了。
- 头发帽子（`cap`）和后脑（`back`）在极角 47°–72° 之间是**同一个半径上的两层壳**，
  会 z-fighting，在后脑画出一条横贯的硬带子，读起来像头发上的接缝。`cap` 放到 `1.004×` 就没了。

### 描边：白厅要暗边，黑盒要亮边

2D 时代她需要一圈描边，因为一张剪影本身没有形体，而近白的剪纸站在近白房间里实测只差 **35 级**。
实体不需要——她被灯位照亮，每个房间的灯里本来就有一盏轮廓光。**但床单例外**：一块发光的白布
没有硬边可抓，尤其在霜厅那种白墙上。

所以描边从"整圈轮廓"改成了"她外面的一层 fresnel 外壳"（`aura`）。真正的机关在**混合模式**上：
看三套房间各自要什么——`studio` 与 `abyss` 给的是**暗色** rim（`#2A2B1F` / `#2E3A3A`），
只有 `noir` 给暖色（`#DCBE8C`）。这是页面在说"白厅里她要有一条边顶住墙，黑盒里她要发光"。
**加法混合只能做后半句**——加一个深色等于加零——所以那条边一直是静默失效的，她于是溶进白厅。
换成**普通混合**之后同一个 shader 两件事都做了：`mix(背景, rim, f·op)` 在亮房间里压暗、
在暗房间里提亮，没有分支、没有按主题分叉的代码。**哪一间看着不对，要改的是 rim 的颜色。**

外壳的半径也是个数：fresnel 在**它自己的轮廓**上最强，所以壳开大了就是"在她外面画一圈"——
那是一道浮着的箍，不是一条边（制服版开在 1.22 倍，特写下是一整个肥皂泡）。
但这一版的壳**不是按身体给的，是按最高最宽的那一件**：最高的是帽冠（最高点高出头顶 0.40 B，
而且因为帽子是歪的，那个点还横着挪出去 0.31 B），最宽的是帽檐（1.72 B）。按身体给的话，
帽子整顶露在光环外面——上一版就是这样，只罩到檐口。现在是
`AURA_H = (TOP − HEM) + 0.55B`、`aura.scale.set(BRIM_R·1.05, AURA_H·0.50, BRIM_R·1.05)`、
`renderOrder = -1`。

同一条还有个容易搞反的：**fresnel 的曲线决定它是一条线还是一条带**。裸 fresnel 在轮廓上是 1、
往里几个像素就归零，画出来是**一像素的线**，不是一条边——白厅里那点对比度根本看不见。
制服版给了一个地板值（`f = 0.70 + 0.30·f²`）把线撑成带；这一版反过来走，用 `pow(f, 2.2)`
一条更陡的曲线，把 `uOpacity` 压到 **0.14**——因为幽灵自己已经有一层体内青光，光环只需要
勾一条边，给多了在霜厅的白墙上会糊成一团雾、把轮廓吃掉。**带宽由壳半径决定、
对比度由 `uOpacity` 单独决定**，两个数管两件事。

还有一条同类的：**`setRoom` 必须在精灵建出来之后再调一次**。`applyTheme` 在解析查询串时就跑过了，
那在 `createGhost` **之前**，所以它那一次 `setRoom` 找不到人、什么也没做——光环会一直停在
占位的浅绿上。白厅里那等于"发光"而不是"描边"，而且冷启动和手动换主题的结果会不一致。

### 嘴为什么"看不见"：canvas 的分辨率不是屏幕的分辨率

> **这一节讲的是制服版**（那时脸是画在 canvas 上、再贴成球面补丁的）。小幽灵的五官全是网格，
> 所以"嘴太小、看不见"这个病在这一版里不存在——但它记着一条对整页都成立的规矩，
> 而那条规矩在这一版仍然咬人（见下面「判她有没有在唱」里 `_sing.mjs` 那条假读数）。

这是制服版里最隐蔽的一处，症状是**她整张脸上没有嘴**——不是画错，是画的东西根本没到达屏幕。

嘴和眼睛一样，是一块球面补丁贴一张自绘 canvas。区别在尺寸：眼睛是 **0.60 × 0.684 弧度**，
嘴是 **0.115 × 0.086**。在 radius 33 那一档（当时的默认机位）1 弧度约 55 个页面像素，所以嘴的补丁只有约 **13 × 10 px**，
而它上面贴的 canvas 是 **160 × 120**——**十二比一的缩小**。canvas 里那条 9px 的笔画到了屏幕上
只剩四分之三个像素，再和透明的底平均一次，就化成了一层看不见的淡影。

判它是"没渲染"还是"渲染了但太小"，靠的是把笔画临时改成洋红、`lineWidth` 拉到 26 再截一张图：
回来的**只有一个点**。于是就知道问题不是几何、不是深度、不是遮挡，是分辨率。

修法是两件事一起做：补丁放大到 **0.40 × 0.26 弧度**（约 24 × 16 px），笔画加粗到 14。
**眼睛从来没出过这个问题，只是因为它们一开始就画得又大又重。**

### 一个 class 属性覆写了三次状态

互动区的每一格有三种态：`.sel`（面板正展示的）、`.done`（场景正展示的）、
`.playing`（**正在动的**，由 `syncMoveButtons` 按模型回读写入）。前两个由 `render()` 每帧算，
第三个有自己的时钟。第一版 `render()` 里写的是

```js
refRows[i].className = 'row' + (i === ri ? ' sel' : '') + (l ? ' done' : '');
```

—— 这是从"一行只有两态"的年代留下来的写法，**整体覆写属性会把第三种态一起抹掉**。
而 `render()` 在同一帧里、且在 `syncMoveButtons()` **之后**跑，所以那个类被加上又被擦掉，
每秒六十次。症状：`?m=02` 打开的是对的条目、她确实在晃，
**只有那一格不亮**。改成逐类 `classList.toggle` 即可。

这条和「嘴」是同一种病：**状态是对的，只有一样东西没到屏幕上**——所以只能从 DOM / 像素去问，
不能从模型状态去问。`tools/_pick.mjs` 现在把 `#ref-list .row.playing` 也读一遍。

## 音乐

### 出厂那一段是页面自己合成的

**这个仓库里不含任何音频文件。** 页面启动时自己算一段：A 面 60 秒、B 面 60 秒，两面六首
（曲目表在 `src/playlist.js`），全部由 `src/demo-audio.js` 在浏览器里**逐采样**算出来——
三角波 pad、扫频贝斯、琶音、底鼓、军鼓、踩镲，走一条带 wobble 与软削的总线，
再手写一个 44 字节 WAV 头包成 blob URL 交给 `<audio>`。零网络请求、零文件依赖，
`file://` 下双击也出声。

这么做是因为原来装的那首是 Matryoshka 的《Sacred Play Secret Place》——商业录音，
公开仓库不再分发（`assets/` 在 `.gitignore` 里默认忽略，只放行随站点发布的那两张图），
克隆下来必然 404。
与其把「加载失败」那条降级路径当默认，不如让页面带一段自己的出版物：
**小幽灵演示曲**，虚构乐队「烛芯」（一支只在城堡里演出的幽魂合唱团）的两面。
A 面 92 BPM 自然小调（Am7–Fmaj7–Cadd9–G6），
B 面 76 BPM 多利亚调式（Dm7–G9–Bbmaj7–Cadd9）——**换到 B 面时听得出来换了调**。
（换面过去是 `F` 键和「翻转」按钮的事，那两个跟着外壳一起收起来了；现在从曲目表点 B 面那一首进，
见「曲目表」。两面之间的差别一点没少，只是入口换了地方。）

合成一次约 0.6 秒（60 秒立体声 / 44.1 kHz）。A 面在启动时算，B 面第一次被切到才算，
算完就记住：blob URL 不回收，切回来不用再算。

> 第一版是拿 `OfflineAudioContext` 搭节点图做的，实测 60 秒要 **20.4 秒**。
> 根因是 Web Audio 每个已连接节点、每个 128 采样量子都要被处理一遍，而节点数随曲长线性增长，
> 总成本是**时长平方**（实测 10 s → 207 ms、20 s → 797 ms）。改成逐采样 DSP 后是 0.6 秒，快 33 倍。
> 顺带把 WAV 编码从 `DataView.setInt16` 换成 `Int16Array` 视图——260 万次写入，这个差别不小。

### 想装一首真的

页头的 **添加音乐**（或按 `O`，或把音频文件直接拖到页面上）选一个本地文件，她就唱它。
曲名 / 艺人 / 专辑读的是文件自己的 ID3 标签（`src/tags.js`：v2.2 / 2.3 / 2.4 与 v1 都认，
UTF-16 与 UTF-8 都认），没有标签就用文件名。跟着一起变的还有：页头的型号铭牌
（`SP—01` → `SP—05` …）、左下角那个芯片、右下角计数器的总长、浏览器标签页的标题。
（从前还会重写磁带标签上的手写体标题与 MINUTES 带长——那台机器收起来之后，这一处没有可见的去处了，
但换带的流程本身还在跑，见下。）

想让它固定下来（一打开就是那首），把文件放进 `assets/`，改 `src/main.js` 的 `TRACK_DEFAULT`
（`title / artist / album / src`），再把 `boot()` 里那一步「正在合成演示音频」去掉——
那一步会用演示曲的第一面覆盖 `TRACK_DEFAULT`。

**换带不是一次硬切**，而且这一段即使在外壳不可见时也照常演完。新的印刷先画在标签上方那层同形状的
副本上，再由一条从左扫到右的写头放出来（写头本身随 `src/cassette.js` 一起删了 ——
外壳收起来之后它只在不可见的网格上跑，见「结构」；调度它的 `main.js` 的 `updateLabelSwap` 还在），
机身同时被压下一点再回弹，配一声走带开关声；写头扫完的那一刻整页才一起换成新的一首，
所以看不到"文字跳了一下"——**芯片、计数器、曲目表是在同一帧一起落的**，这一条现在是它唯一看得见的部分。
（那台磁带自己也一样：`cas` 每帧都还在被驱动，只是不画。理由见文件开头。）

再放一首就是替换上一首（只有一段曲目）；刷新页面回到出厂那一首；重置 也把它放回去。
文件不上传到任何地方，也不会被存进浏览器——它只是被 `<audio>` 指着的一个 blob URL。

完全没有音频时页面走「音频加载失败 · 她只做口型」那条降级路径：**她照样唱**——呼吸、浮沉、歪头
一个不少，因为她的信号取自**走带台在不在转**，而不是 `<audio>` 在不在出声（两者分开的理由见「换脸」）。
走带与倒带也照常演，只是没有声音。
放完一首会自动快速倒带（`REW_SECONDS = 8.5`，计数器变铜色），倒完从头再放，循环。

### 曲目表

总目录（`I`）里，五个互动动作下面接着**曲目表**：两面六首，一行一首，印着所在面、起点、时长。
点一首就是「装那一面 + 跳到那一首的头」，走的是和手动拖滑轨同一条路径（`seekTo`），
所以滑轨、计数器、`#now` 芯片不会各说各话。**这也是 B 面现在唯一的入口**——换面过去从前是
`F` 键和「翻转」按钮的事，那两个跟着外壳一起收起来了。

左下角那个芯片跟着播放的**当前位置**走，而不是跟着"最后装进来的是什么"——
一面是连续的一段音频、三首是它上面的三个区间，"现在放到哪一首"只有 `currentTime` 答得上来。
（`main.js` 的 `syncNowTrack()`，和计数器共用同一个 0.2 秒节流。）

## 交互

页面是一张美术馆展签：她可以做的 **五件事**排成互动区那一行五个格子，`↓↑` 换一件，`←→` 换机位，
`回车`（或**直接点那一格**）做一次。**做一次是唯一会改变画面的动作**——
浏览只移动游标，镜头不会在你挑的时候从底下动起来。

除了那张清单，她自己也接得住，而且四条路各管一件事：

| 怎么碰她 | 她怎么应 |
| --- | --- |
| **点她一下** | 打招呼：点头 / 晃一晃 / 掀帽轮着来（`GREETINGS = ['nod', 'wave', 'salute']`——`k` 说身份、显示名说事实）。**不改清单的选中项**，所以底部「动作 01/05」照旧，而清单里亮起来的是真正在动的那一行（`.playing`） |
| **光标停在她身上** | 抬头看你：整颗头转 `aimX · 0.30`、身体前倾 `aimY · 0.10` 并侧倾 `aimX · 0.16`（都乘一个 `st.aim` 的淡入量）。不是屏幕正中算的——她自己的屏幕位置每帧都在动，所以先 `head.getWorldPosition().project(camera)` 求出**她**在哪，再取指针与她的差（`aimAt`，增益 `AIM_GAIN = 1.45`） |
| **跟节拍** | 鼓点上整个舞动一起涨：抬升、左右摇、转身、帽子迟一拍、扫帚迟一拍，都乘同一个 `st.beat`。喂给她的是**节拍**不是电平：`viz.pulse` 是"高于自身慢均值的量"，0..1，乘 `PULSE_GAIN = 3.2` |
| **光标离开画布** | 收回来（`pointerleave`）。不然她会一直朝着光标最后出现的地方看，那读起来像 bug 而不像注意力 |

> 底部的键帽那排是**按可用性分级**的（`data-p`），窄屏先丢低级的。从前是 11 项，现在 **9 项**：
> `E` 拆解与 `F` 翻面跟着它们镜像的两个按钮一起没了。

| 操作 | 效果 |
| --- | --- |
| `↓` `↑` / 点列表 | 前后换一个动作：点头 / 晃一晃 / 转个圈 / 跳一跳 / 掀帽（`k` 仍是 `nod` / `wave` / `spin` / `jump` / `salute`——深链 `?m=0N` 与 `ghost.js` 的 clip 名都 key 在它上面） |
| `←` `→` | 切换机位：正视 / 等轴 / 俯视 / 细节特写（radius 23 / 33 / 34 / 21；**01 号是正视，也就是默认机位**）。切到「细节特写」时镜头推得很近，她会占掉画幅的一半以上，所以**「细节特写」就是"面板收起"的机位**：选中它整块面板直接自己整个收起（不是先变短再收）、只留编号与读取按钮，不用点收起；离开这个机位自动展开回来。在那儿手动展开的话退回到收回 34%、规格表留着那一档 |
| `回车` | 做一次 `↓↑` 选中的那个动作。点格子是直接做，不需要先选中 |
| `I` / 目录 | 打开总目录：五个动作列成卡片，卡片上印的是 `note`——**她做什么**，不是镜头去哪（机位跟着动作走的那套 2026-10-02 拆了，见「做一次动作会做什么」）；下面接**曲目表**（两面六首，点一首跳到它）。点动作标题直接做一次 |
| `O` / 添加音乐 | 换一首自己的：选本地音频文件，芯片、计数器、曲目表与页头编号一起换（见「音乐」）。拖一个音频文件到页面上效果相同 |
| `,` / 设置 | 打开设置页（见「设置」）。齿轮在悬浮时转 1/4 圈并放大，打开期间保持转过去的状态 |
| `Esc` | 退一层：总目录开着就关目录，否则展开收起的面板。（代码里还留着"合上拆解"那一档，但它现在够不着——`exploded` 没有任何入口能变成 true，见下面 `TAPE_ON` 那一段） |
| 收起详情 | 折叠右侧正文（只留编号与读取按钮）。两拍：正文先上下合拢，随后**整张纸**向左边缘收回 60%——纸的左边缘就是那条线，面包屑、编号、读取按钮都印在纸上，所以它们跟着纸一起走，纸变短而字不掉队。同时她向画面中间挪（`viewShift` 0.155 → 0.05），把腾出来的地方占上。展开是同样两拍倒放 |
| 拖动 | 旋转（带惯性阻尼；松手 3 秒后缓慢自转） |
| 滚轮 / 双指捏合 | 推拉镜头。**推近时面板跟着一起变短**：静止时本来就让出 20%，从默认机位（radius 23）推到最近的 11，再线性让出 30%（`--retract` = 20% + `--give`）。**推到接近最近（让出 45%，线只剩自己长度的 55%）时面板才自动整个收起**——再往里确实没剩多少档案可读，不如照「收起详情」那样让开；**往回拉一格（让出降到 45% 以下）就自动展开回来**——收和展是同一条线，滚轮回到刚才离开的位置，面板就回到刚才的样子。判定做在**越过**那条线的瞬间，不是看滚轮停在哪一侧：否则「收起详情」会按不动（每帧都会被滚轮按回去）；两次越线之间，手工收起或展开的状态照旧保留，不在临界点上跳。阻尼走的就是折叠那条 `margin-left` 过渡，滚轮还在转的时候只是在挪一个会动的目标；往回拉超过默认机位也不再变长，因为退开不是面板该占画面的理由。正文窄到 282 px 以下时让位的是标题行右端那句提示语——互动区不再整个让位，五个格子在那里仍然放得下 |
| 双击 | **动作从上到下一个一个往下换**（2026-10-03 用户要求）：每双击一次，选中的动作往下走一行（01 → 02 → … → 05 → 01）**并立刻做出来**，点亮的行跟着走。从前它把镜头拉回 01 号机位，2026-10-02 拆掉了（`controls.js` 里那个 `_onDbl` 连同 `onReset` 口子一起删了），那之后到 10-03 之前它什么都不做。**点在哪里都算，不要求正好点中她**：她一直在慢慢浮，要求命中一个会动的目标等于让这个手势只能靠运气触发。要回位就拖一下，或者用 `←` `→` 重新点一次当前机位 |
| `空格` | **演唱 / 暂停**。按钮那一半是原来的走带台（两轮同向转动、带盘半径按带面积守恒实时变化、计数器 = 歌曲进度、放完自动快退重放，并叠一层底噪与马达嗡声——那台机器收起来了，但这一整套照旧在跑）。左下角芯片上「待机 / 演唱中」两个词在 `body.playing` 上交叉淡入，所以那一侧一行 JavaScript 都不用写 |
| 点她 | **打招呼**（不再切播放——那个归 `空格`）。一条射线打到一个**隐形的胶囊代理**上，不是她身上那些真网格：薄片当靶子会被打穿，而且真网格每帧都在动，靶子会在光标底下晃。`material.visible = false` 不参与渲染，但 `Raycaster` 只看材质在不在，不看那个标志。拖拽（位移 > 6 px）、长按（> 500 ms）、以及点在空地上，三种都不触发。**双击不再是"两次打招呼"**：320 ms 内的第二次点击被读成一个手势，走上面那条「换动作」——所以双击她 = 先打个招呼、再换一个动作 |
| 拖 / 点滑轨 | 定位：计数右边那根滑轨，拖动、点哪跳哪，`←` `→` 微调，`Home` / `End` 到两头。有声音时同时写 `currentTime` 与带位（`cas.setProgress`），所以带子和声音落在同一帧；没有音频时它走的是画面自己的时钟。**正在快倒时拖它 = 把带子拿走**：那一趟作废，走带台停在放手的地方（方向键被聚焦的滑轨截住，不会顺手换机位） |
| `M` / 静音 | 只关掉声音，演唱继续 |
| 喇叭上滚轮 | 调音量：5% 一档，默认 30%。图标上会浮出当前档位，弧线也跟着走（过半亮两道）；滚到 0 就是静音，往上滚第一格解除静音。滚轮在这个按钮上被就地截住，不会同时推拉镜头 |
| `A` / 巡览 | 自动环绕开关 |
| 右上三格 | 换光环境：晴室 / 夜巢 / 深潭。环境光、背景、灯位、后期参数整体过渡。**`data-theme` 的值还是 `studio` / `noir` / `abyss`**，没跟着名字改——它同时是 localStorage 里那个 `t`、是 URL 的 `?t=`、是三张 `THEMES` 表的键，改一个就断一串 |
| 重置 | 回到初始状态：01 号动作、正视机位、晴室光环境、停止演唱 |

`prefers-reduced-motion` 下整套动画退成"切"：不放片头、不呼吸浮动（她的钟被停住而不是放慢——
`t = 0` 正是她建模时那一帧，所以她静止地停在休息姿上）、**唱歌时不再自己起动作**（`main.js`
传的 `routine` 就是 `!reduce`：那是环境动作，不是你要的那一下）、镜头换机位直接落位、
面板折叠与随镜头变短、主题切换不做过渡。状态变化本身都还在，只是不再一路走过去。

### 做一次动作会做什么

**从前是三件事，现在只剩一件。** 读一条零件档案会让机身打开、该零件留在真实材质上、其余零件退成
一层暖灰的半透明幽灵，同时只留该零件那一条引线——**这一整套跟着外壳一起收起来了**（`TAPE_ON`），
连带 `ANNOS` 也清空了（三个消费方都只是遍历，空列表让它们无事可做，一行 `if` 都不用加）。

**留下来的只有她做那个动作。镜头不动。** 原来五个动作各自带一个 `view`（为那个手势选好的取景），
选中就花 1.6 秒把镜头摇过去。两件事是错的：访客要她点头，不是要被重新取景——而镜头的行程比点头
**更大**、同时到达，最后你看到的是运镜；更隐蔽的是那个 `view` 让 `vi` 可以是 −1，而 `vi < 0`
本来已经有一个意思——"外壳打开了，没有机位可报"。一个变量两个含义，读数只能猜。
镜头现在只属于访客（`VANTAGES`，`←` `→`），动作只是一段姿态。

**四条路都走同一个函数**（`doMove`）：互动区那五个格子、底部的刻度、总目录的卡片、`回车`。
所以**动作不可能和别处各说各话**——这比"记得在四处都改一遍"可靠。
（`doMove` 还会顺手取消待回位的那次 `homeArmed`：行一点下去，就没有东西会在她表演的时候
横穿画面。）

规格表里的颜色是**反照率，不是采样值**：`PROFILE.spec` 里那三行就是 `src/ghost.js` 顶部 `C` 的
`hatTop` / `hatUnder` / `band`（帽面靛紫 `#372370`、檐底猩红 `#C62B2B`、金带 `#C9A24E`），
所以档案描述的是模型本身，而不是一个关于模型的想法。原始色值是从参考视频的成品渲染上采的
（7×7 中值，`_ref/ghost/palette.py`），但采到的是**那盏强主光下的受光色**，直接写进图鉴会跟模型
对不上，所以两边都放反照率。`C` 的注释里写着这条规矩：**改 `C` 就得改这里**——上一轮漏改过一次。

面板本身也收成了**一页**：从前是六条档案（本体 + 五个部位），现在是 `PROFILE` 这一页人物介绍
加上 `MOVES` 那五个动作格。`render()` 于是有两个来源——`PROFILE` 那半用 `dataset.no` 打了戳
（每次方向键都重建会丢掉 hover 状态，规格行本来就是这个规矩），`MOVES` 那半只是切 class，不要钱。

下面两段讲的是**拆解时的幽灵态**，也就是被收起来的那套外壳渐变（`TAPE_ON = false` 时它在不可见网格上跑，
所以 `applyFocus` 外面加了守卫）。留着是因为它是这套材质动画唯一的书面记录。

**幽灵是渐变过去的，不是切过去的。** 幽灵的每一条特征——灰、平、透——都是靠动画材质自己的
uniform 走到的：颜色、粗糙度、金属度、清漆、法线强度一起走到目标值，不透明度最后跟着下去
（`paintGhost`）。旧版是直接换成一块半透明的灰料，在一段缓入的运镜和一段缓出的拆解中间，
那一下硬切看起来像卡了一帧。

渐变用的材质副本必须**每个 mesh 一份**：原件是共享的（`M.shell` 被好几个零件同时指着），
改一个就会改一片。副本第一次用的时候克隆一次、之后一直留着，之后每帧只改 uniform，
**不触发任何 shader 重编译**。折叠/展开、换主题这些路径上也不会漏——探针重新绑定时会连
正在渐变中的副本一起更新。

标记（右侧列表的行、底部那排刻度）也是**建一次、之后只切 class**，不再每次重新生成：
新建的元素一出生就是终态，过渡动画根本不会播，那才是切编号时"跳一下"的来源。

## 界面

页面本身是一件印刷品叠在一张照片上。几条决定值得记下来，因为它们都不是装饰。

### 一份档案 = 一张纸

所有用文字说的东西都印在**同一块半透明纸**上（`.sheet`），挂在右侧三分之一处。
在这之前，字是直接压在画面上的：只有靠主体恰好待在左半边才好读，地面一亮的那些角度
就是灰压灰。纸给这份档案一个自己的明度，**对比度不再取决于相机在哪**；主体也因此可以
从它后面过去——一张文件盖在照片上，本来就该是这样。

纸**自己带着那段落差**（`margin-left: var(--retract)`），不是让里面的字各走各的。折叠、
滚轮推近、「细节特写」这三种收法走的是同一个数，而百分比外边距在两个**包含块不同**的
子元素上会算出不同的长度——纸和它上面的规矩线迟早会错开几个像素。一个元素动，
纸、线、字就不可能散架。左上角那道 2px 的铜色短线是它的定位角标。

### 纸有多长：钉在页头与走带台之间

纸的长度不是它自己的事。`--panel-half` 是它的**一半**，`top` 由它算出（`50% - half`），
所以「居中」等于「上下各溢出一半」：窗口够高时这是对的，窗口一矮，同一块纸会同时压到
页头和走带台上。实测 1440×600 时纸顶越过页头底边 11px、纸底越过走带台顶边 20px；
1100×460 变成 70px 与 56px，五个动作格子直接印在计数读数上（1612px² 的字压字）。

所以长度由测量决定，三个数（都在 `pinPanel` 里）：`--panel-half` 用来居中，
`--panel-top` 说它允许从哪开始，`--band` 是页头底边到走带台顶边那条带有多长、也就是
它的上限。钳位是照着「纸本来就装得下的每一档，逐像素等于旧的 `50% - h/2`」写的，
所以 **600px 以上视口的一切都不动**：1440×820 存的 top 是 212.4px，正是
`50% - 197.6px`；1440×600、1200×500、1100×460 才被钳住，落在带子里（`collisions=0`）。

★ 这一条踩过两次同一个坑，两次都不是布局的错，是**读的时机**：`resize` 里强制布局读到
的是**过渡中途**的版面。`.sheet` 带 `.58s margin-left`、`.dossier` 带 `.7s left`，而页头
自己的底边在 resize 之后还要动三分之一秒——1092×588 上 `+0ms` 读 117.4px、`+400ms` 才
落到 114.5px。第一版钉在中间版面上，`--panel-half` 报 208.7px，而纸实际 368.9px 高
（一半 184.5），**差 23px**。修法是两层：按**纸的宽度**观察而不是窗口宽度（记录换行才改
宽度，记录变长不改——变长是 `.dbody` 的事，它只用来决定要不要出滚动条），再用
`setTimeout(…, 700)` 而不是两次 `requestAnimationFrame`：软件渲染下一帧是「秒」，
两次 rAF 可能是 30ms 也可能是 6s，同一份构建因此一次量出 351.8px、下一次 369px。
观察者自己的回调里也**不做布局**——它写 `--band`、`--panel-top` 和 `.overflow` 类，而
「在回调里改变被观察对象的尺寸」是 Chrome 报 `ResizeObserver loop completed with
undelivered notifications` 的成因；那是一条**页面错误**，而这个仓库的探针按页面错误判失败：
`_dbl.js` 与 `_song.mjs` 的每一条断言都是绿的，两次运行仍然红。挪到下一个任务（`setTimeout 0`）
就好了。
`pinPanel` 里还有两件同样的事：量之前先把 `.overflow` 摘掉（`scrollbar-gutter: stable`
会让记录在一条窄十五像素的栏里折行），以及 900 以下把这三个数**删掉**而不是留着上一档
的残值——留着会读成一个测量值，而它什么也不是。

★ 上限能回来，是因为当年反对它的理由不是「上限」，是**静默**。被截掉的那段记录既没有
滚轮也抓不到滚动条（`.ui` 是 `pointer-events: none`），于是「少一段」和「少一段而且
够不着」成了一回事——1080 上藏掉 55px 含面板的「读取」键，1000 上 193px。补上的是
缺的那一半：`.dossier.overflow .sheet` 在**真的溢出时**才把指针收回来，装得下的记录
照旧——在纸上拖一下仍然是转模型。

### ≤900：纸变成一张底页，上限得重算

900 以下纸挂在底部（`top: auto; bottom: 20rem`），上限是它自己的 `max-height`。那个数
原来写的是 `calc(100vh - 36.5rem)`：给纸底下留 584px，而多数小窗口并没有这么多家具。
实测纸的底边在 `100vh - 20rem`、页头底边在 133.4px，所以带子其实是
`100vh - 453.4px`（= `28.34rem`），多出来的 130px 是白扔的——900×700 上纸只有 116px 高
却要装 289px 的记录，三十五行的九行。更糟的是视口高不到 584px 时那个 `calc()` 变成
负数、被钳到 0，纸塌成只剩内边距：900×584 与 880×520 都是 **40px**，`now` 芯片直接印在
面包屑上（1159px²）。

现在是 `max(calc(100vh - 28.34rem), 5rem)`：900×700 的纸从 116px 回到 246.5px，
900×584 从 40px 回到 130.5px。地板才是拦住塌陷的那个数，而它是有代价的——视口高过
大约 520px 之后纸**必须**压到页头上，因为没有地方可给了，而一张读得出来的纸好过一张
空纸。760×420 是这条取舍的极端：纸只有 80px，仍然压着页头（4999px² 的字压字），
而且没有便宜的解——那一档的页头 131px 加走带台 197px 已经吃掉 420px 里的 328px。

### 一个旋钮：根字号

界面上每一个长度都是根字号的倍数（`tools/_px2rem.mjs` 把整张表从 px 换成了 rem），
根字号是 `clamp(16px, 1.1111vw, 21px)`：**1440 下正好 16px，和手写 px 一模一样；
2560 下是 21px**，纸、字、控制台、发丝线一起长 1.31 倍。不这么做的话，2560 上就是
一套 1440 的版式铺在更大的画布上——纸会拉到 1108px 宽、中间空成一块板。
`border` 与 `outline` 刻意留在 px：发丝线在任何缩放下都是一个设备像素。

纸本身还有个宽度上限（`--plate-max`）：超过之后它不再变宽，由主体和纸之间的留白去变宽。

### 一套状态，处处一样

rest → hover → **press** → focus → on。hover 永远是铜色，press 永远是下沉 1px，
focus 永远是同一道铜色发丝线加偏移（`:focus-visible`，从不是只换颜色）。滚轮、上下箭头、
键帽、纸上的行，用的都是这一套。

### 底部控制台

`1fr auto 1fr`：两侧等宽，中间的翻页块因此**落在画幅自己的中线上**，不管右边的走带台
长到多少。从前它是绝对居中的，根本不知道右边还有个走带台——1440 下「正视机位」是直接
印在播放按钮底下的。

走带台是一行：演唱 / 计数 / 滑轨 / 两个字形，全都**裸印在画幅上**，没有自己的框。
（那两个字形现在是巡览与静音；从前是四个，拆解与翻转跟着外壳一起收起来了。见下面
「断点」一节。）

它原来是两行的、外面还套着一个带描边和底色的卡片：上排走带 / 计数 / 四个圆钮，下排整整
一行留给滑轨。那个框什么也没多说（上面的档案纸本来就带着同一层底色和发丝线），却在窗口
不够高时**把一块亮方块直接盖在档案面板的最后几行上**——走带台是印在画幅上的，那就让它
读起来像画幅的一部分。滑轨也一并挪到计数旁边，顺带把这条的高度减掉一行。

那两个字形的圆环**静止时是透明的**：一排环压在纸面上，读起来是"按钮落在画幅上"，
而不是"印在画幅上的记号"，和这一行的来意正相反。
环没有删掉，只是**收起来**——`border-color` 由 `var(--hair)` 改成 `transparent`，
`:hover` 和 `.on` 照样把它画出来，所以**"哪一个开着"的提示、以及点击热区都没变**，
静止时又只剩字形本身。

### 断点：≤1080 时 deck 排三行

`.deck` 在 1080 以下是 `grid-template-areas: "sel" "pager" "right"` —— 一行三列变成三行。
这不是排版偏好，是修一个 bug：走带台的顶边在断点两侧**不连续**（≥1100 是 `vh−82`，≤1080 是
`vh−167`），跨过 1080 的那一帧它会跳高 85px，而 `.sel` 的缩放动不了它。三行之后它回到带子该在的
位置，分页器仍跨整行、仍落在画框中心线上。

> 这一条值得记下来，因为**它同时是 `tools/_resp.mjs` 那个假旗标的来源**。deck 是一个**没有底色**
> 的透明网格，而三行里的头两行**在右侧是空的**——右侧正是纸面所在。于是 1080 与 1000 两档会报
> `deck∩sheet 48629px² / 55049px²`，而那个带里**什么都没画**：`.sel` 靠左（`justify-self: start`）、
> `.pager` 居中、`.deck-right` 在第三行、纸面到不了那么低。探针自己的注释早就写着"deck 是透明网格，
> 它自己的盒子压在纸上没有意义"，可旗标还挂在盒子上。现在旗标改成量**被画出来的东西**
> （`transport / sel / pager / deck-right / now` 五项），盒子那个数只印在表里、不报。判"压到没有"
> 要墨水对墨水，不是盒子对盒子。

### 位置滑轨

`<input type="range">`，不是套了指针事件的 div：拖动、点哪跳哪、方向键、Home / End、
slider 角色全都自带，而设置页里本来就有一个同样的 range，于是**滑轨和那根调子看起来
就是同一个零件**（都是 `--p` / `--fill` 拉一根渐变）。播放时它跟着计数器同一个节拍走；
有手按在上面时（`scrubbing`）循环不许回写，否则拇指会被两头拉扯。

拖动会**结束**一次快倒而不是打断它：带子被人拿走、那一趟作废、走带台停在放手的地方。
`dir` 必须手动扳回正向——留在快倒上，再按播放会一路倒到底。

### 键帽

底部那排键，每一颗是一个真实按键加它干的事。`data-p` 给它们分级，窄屏先丢低级的，
而不是让这一行折进控制台。**按键时对应的键帽会亮**（`.hit`），于是这排字从说明书
变成了读数。

### 互动区是五个格子

一格一击。每格两行：编号在上、名字在下（`01` / `点头`）。点下去**直接做**，不再有
"先在列表里选中、再按纸底下那颗按钮执行"的第二段——那颗按钮 2026-10-04 删掉了，
它的职能被格子吸收。

三态落在格子上：`.sel` 是面板正在展示的那一格，`.done` 是场景正在展示的那一格，
`.playing` 是**正在动**的那一格——只有它是短暂的（动作放完模型自己把它清掉），
所以它允许最响，也因此点她可以点亮一格既不是 `.sel` 也不是 `.done` 的。

**为什么是竖排两行，不是"编号 名字"并排**：纸的正文在 1092×588 上只有 322px 宽，
五格一行每格 61px，而「02 晃一晃」并排要 67px（13 编号 + 4 间隔 + 38 名字 + 12 内边距）。
竖排把最宽的一格压到 38px 的文字，一行就装得下；折成两行格子要多花 34px，而那一档的
高度预算只有 371.9px。

**为什么编号行右端挂着一张网**：蛛网与那个小幽灵原来在纸的右下角，注释写着"四分之一张
纸上任何记录都到不了的地方"。五个格子搬过去之后那句话就不成立了——画在按钮下面的网，
是一个读不出来的按钮。编号行右半边是纸上最后一块空地，而编号下面那条横线正好从它中间
穿过，一张网挂在那里比挂在角上更合适。

规格表那行关键字和数值之间是**虚线引带**——档案卡最老的做法，在这里干的是真活：
这么小的字，眼睛本来会从标签滑出去、找不到它后面那个数。

### 对比度

`--ink-faint` 定在 .60（≈4.7:1，够 AA 小字），夜巢那间 .58，晴室的印泥红 `#c8362b`
对白纸约 5.4:1，`.doc-note` 一类正文保持 6:1 以上。另有
`@media (prefers-contrast: more)`：发丝线与微标签一起加深，纸也变实，三套房间各一份。

三间屋子现在是 2 亮 1 暗：晴室的纸 `#f5f4f1`、深潭的 `#e5eaee`、夜巢的 `#0c0c0e`。
**纸是半透明的**（`--sheet-a`），它下面压的是三维场景的背景，所以同一个 token 值在不同
房间复合出来的纸面不一样——纸面用 `color-mix()` 而不是一个实色就是这个原因。实测档案纸
正文、面包屑与副标题在放大图上都仍然清楚（这是拿 `getBoundingClientRect` 的矩形去截图像素
的结论，不是目测）；真正需要小心的是**三维背景上的字**，也就是右上那三格按钮——它们跟着
所在房间的墨色走，三间屋子里都读得出来。

底部那条重复的品牌条删了：页头和右下角各说了一遍，第三遍只是占着走带台
旁边的位置。（页头和右下角现在也不再说这个词了，见「换脸」那一段。）

### 动效：没有一帧是切过去的

一次一个属性地加过渡是不够的——**剩下的硬切几乎都是"写法"造成的**，不是漏了声明。

**主题是一整套 token，所以过渡要加在 token 上。** CSS 不能过渡未注册的自定义属性，
于是 `data-theme` 一换，十八个 token 在同一帧全变：body 自己那 0.9 秒在淡，而纸、
控制台、两个浮层、以及它们身上每一道发丝线是**跳**过去的。`@property` 给每个 token
注册了类型与初值（`styles.css` 顶部），它们就变成可插值的了，过渡因此能写在根上，
读 token 的一切自动跟上——**包括任何别的方式都插不了值的东西**：渐变色标、`color-mix()`
的结果、box-shadow、`backdrop-filter` 的色调、纸面那道内侧高光。一处声明，
替掉一张还要跟着以后每条规则维护的清单。相应地，各元素自己那些 `background .9s / color .9s`
全删了：同一次变化被缓动两次只会变得发糊。

**房间块必须写成 `html[data-theme="…"]`，不能只写 `[data-theme="…"]`。** 右上那三格按钮自己
就带着 `data-theme`（点击处理器靠它知道该进哪间屋子），所以一条裸的属性选择器**也匹配按钮**，
于是每个按钮把整套 token 又在自己身上声明了一遍——结果是按钮永远被涂成**它自己命名的那间屋子**，
而不是你正站着的那间：在晴室里「夜巢」和「深潭」解析成夜巢和深潭的近白墨色，落在浅色纸面上直接
看不见；在深潭里「夜巢」和「晴室」解析成前两间的深墨色，沉进蓝色里。只有当前那一格是对的，
而它只是因为 `.on` 用的是另外两个 token。一个元素级的 `html` 限定就够了。

**文字与数字各有一个助手**（`main.js` 顶部）。`textContent = x` 是在两帧之间换掉字形，
那就是切：`swapText` 让旧词向上走、新词从下面来，飞在半路时再来一次只改目标（按住 ↓
走机位读数不会闪）；`riseText` 只做"来"，给加载页那行每一步都要换的状态——两段式在那里
反而更糟，间隔只有一帧，前半段永远走不完，整行会黑着加载完。`setRoll` 用来滚数字：
计数器、时钟、页头的编号、音量读数、调子，文字建一次、一个字符一格，**只有变了的字符
在动**（旧字从格里升出去、新字从格下面升上来，就是磁带计数器的样子）；格子右对齐，
所以 `0%` 变 `100%` 是加一格而不是重建，个位永远不挪。数字用 tabular，格宽前后一样。

`swapText` 的**落地是定时器的事，不是动画 `finish` 事件的**：动画时钟被节流时（后台
标签页、省电模式、无头渲染器）`finish` 可能永远不来，读数就会一直挂着旧词——会撒谎的
读数比会切一下的读数更糟。动画只管好看，到达是承诺。

**图标换的是字，不是显示。** `display: none → block` 天生不可过渡，而演唱/暂停是
全页按得最多的那个钮，那一帧跳变最扎眼。两个字形本来就画在同一个 16×16 里，于是改成
交叉淡入：三角缩小转开、两道竖条升起来（0.24s / 0.34s，静音那组喇叭弧线与叉同款，
音量过半的那道弧也从"显示/不显示"变成淡入淡出）。

**折叠箭头画出来了，不是字形。** `content: '▾' → '▸'` 也是不可过渡的；现在是
border 画的一个三角在转 90°，而按钮说的正是纸要往哪边走，转就是信息本身。

**滑轨的填充是自己的元素，不是渐变的一个色标。** 色标插不了值，点滑轨或按 Home/End
时墨迹是瞬移过去的；换成一条会缩放的 `.rail-fill`（`transform: scaleX(var(--p))`）
之后它可以过渡，而且走合成器。设置页那根调子现在是同一套零件（`--p` 一个数，
两条滑轨一个语言）。

**级联**：换档案时规格表逐行升起来（`--i` 是建行时写进行上的序号），总目录的卡片、
设置页的行同理——一次重写是一串动作，不是一整块。

**还有一处是布局而不是过渡**：收起档案时，纸向右收的那一拍会把面包屑挤到第二行，
于是那块区域在折叠途中向下长了一行。现在面包屑**不换行**，让位的顺序是固定的——
档案前缀先收成零宽（走折叠自己的第二拍），名字再退成省略号，而「展开详情」永远不缩
（它是唯一的回头路）。任意收回比例下面包屑都是同一行高。

`prefers-reduced-motion` 也从一张选择器清单换成了 `*`：当一个页面的全部要点就是
"没有一帧是切过去的"时，手写的例外清单会在下一个细节被动画化的那一刻过期。

## URL 状态（便于截图/分享）

```
index.html?v=front&t=studio&p=1&m=04&ui=0
```
`v` = front|iso|top|detail（**默认 front**，也就是 01 号机位），`x=1` 拆解，`f=1` 翻转，`t` = noir|studio|abyss，`p=1` 播放，
`m=03` 直接选中并做一次该编号的动作，`spin=0` 关掉自动巡览，`ui=0` 隐藏界面，`intro=1` 强制播放片头，
`fps=1` 显示帧率 / 每帧 JS 耗时 / 当前 dpr / 主体的横向偏移量（`off 当前值→目标值`，调构图时用）。
`x=1`、`f=1`、`m=` 与 `t=` 都是**即时落位**的（不走过渡动画），方便截图。

> **`x=1` 与 `f=1` 现在什么都不做。** 它们指向拆解与翻面，那两个跟着外壳一起收起来了，
> 所以在 `applyQuery` 里被包进了 `if (TAPE_ON)`。两个参数**留在解析表里**是有意的：它们描述的是
> 这台机器本来就有的两个状态，`TAPE_ON` 一旦拨回 true，深链立刻又是对的。`?x=1&f=1` 不会报错，
> 只是没有东西可展开。
>
> `t=` 的取值仍是 `noir|studio|abyss`，**不是**按钮上印的那三个词（晴室 / 夜巢 / 深潭）——
> 它同时是 `THEMES` 的键、localStorage 里存的那个 `t`、和 `html[data-theme]` 的值，改一个断一串。

`t=` 是这里面唯一一处"走两步"的：`setTheme(name, true)` 的 `first` 对 IBL 和背景本来就是"铺好，不是走过去"，
但灯、曝光和后期那半截仍然从启动时那间屋子**缓动**进来——所以 `?t=noir` 会以晴室开场再用 1.6 秒变成夜巢，
截图正好抓在半路。现在 `first` 会连 `applyTheme(0, true)` 一起调，深链是**开在那间屋子里**的；
用户点按钮换环境走的是 `first=false` 那条路，过渡一点没少。
`intro=1` 时片头拥有镜头，`v=` 与 `m=` 自带的机位不再抢占它（其余状态照常生效，所以
`?intro=1&m=03` 是"放片头，同时把 03 号动作做一次"）。

## 换脸：这一版动了什么

> **这一章按换脸的顺序倒着写：最新的一次在前。** 第五次是**小幽灵**（就是画面上的她），
> 第四次是 JK 制服——下面凡是讲"叶冠 / 马尾 / 百褶裙 / 乐福鞋"的地方，说的都是第四次，不是她。
> **讲渲染机器的那几节（灯光 / AO / 后期 / 界面 / 音乐）逐字仍然有效**——机器没有换。

### 一个开关，四样东西

`src/main.js` 顶上有一行 `const TAPE_ON = false;`。它是这一版唯一的总开关，关掉的是**四样**，
每一件都有它非关不可的理由（注释里逐条写着）：

1. **`cas.root.visible = false`** —— 隐藏外壳。注意**不是** `cas.group.visible`：GHOST 是
   *同一批网格换了一套材质*，不是第二个网格，所以隐藏父级会连幽灵一起藏掉。
2. **`ANNOS` 置空** —— 那五条引线标注命名的都是看不见的零件，留着只是一遍遍遍历空内容。
   行本身保留着，因为它是拆解图那些数字唯一的书面记录。
3. **`applyFocus` 的 traverse 加 `if (TAPE_ON)` 守卫** —— 否则 ghost walk 会在不可见网格上
   换材质、为无人观看的淡出重编着色器。
4. **拆解 / 翻面** —— 这两个动作唯一指向的就是外壳装配，见下面「保留下来的」。
   `flipSide()` 留着没删：它是 `playSide` 唯一的调用方，而**B 面没有被锁死**——`buildIndex`
   一直遍历 `SIDES`，曲目表一直是两面的入口。

### 还活着的

**`cas` 每帧都还在被驱动**，只是不画：走带动力学、拆解插值、标签扫描、幽灵渐变一个都没停。
这不是偷懒，是让 `TAPE_ON = true` 能一行回去。

真正的音乐链路一字节没动：`demo-audio.js` 的逐采样合成、`playlist.js` 的曲目表、
`tags.js` 的 ID3、滑轨 / 计数器 / 循环 / 底噪 / 马达声、`viz.js` 的声画联动。
换带那一段写头扫描也照常跑完（芯片、计数器、曲目表在同一帧一起落），只是不再有磁带标签可写。

**她要的那一路信号和频谱柱不是同一个**（`main.js` 主循环里 `sheSings` 与 `musicLive` 分开算）：
频谱柱是**测量**，只有 `<audio>` 真的在出声才跟得上；她是**表演**，只要走带台在转就该唱。
两者分开的那一刻正是"根本没有音频"——那时转轮仍由本地时钟驱动，而芯片上印的是
「音频加载失败 · 她只做口型」，一个纹丝不动的精灵会当场戳穿那句话。

### 素材：交付的其实不是透明 PNG

> **下面两节讲的是 2D 那一版**（她是一块 billboard 的时候）。3D 之后运行时不再读任何图，
> 所以"贴哪张、描边怎么加"都已经是历史；留下来的理由是它们记着**配色是怎么采出来的**
> 和**描边这条需求是怎么来的**——后者在 3D 里换了个形式活下来，见上面「描边：白厅要暗边，黑盒要亮边」。

`assets/spirit.png` 是交接单上写的那张，但实测它是**黑底 JPEG**（`ff d8 ff e0 … JFIF`、
`mode RGB`、无 alpha），51% 的像素亮度低于 10。直接贴上去，房间里会飘一块黑底方板。

`tools/key-spirit.py` 把它键成透明：**不能用边界 flood fill**（叶冠、发缝、裙褶之间有大量
被主体包住的"透过去的背景"黑，会留成黑斑），所以走一条全局亮度斜坡，`L0=12, L1=30` ——
主体内部最暗的像素是 **31**，一个像素都不掉。边缘做 **un-premultiply**（`rgb / 覆盖率`），
否则 three 的 NormalBlending 会在软边上压出一圈黑。最后裁到墨迹框，**这才是 `center` 能取
"她两脚之间"的前提**。

运行时贴的是 `assets/spirit-cut.webp` 而不是 PNG：RGBA PNG 289 KB、PNG-8 63 KB、WebP q88 65 KB，
而 libwebp 的 alpha 是**逐位无损**（实测 max delta = 0），PNG-8 却把 alpha 一起量化
（0.9% 的像素 alpha 误差最大到 39）——**那个软边是她唯一的抗锯齿**，Sprite 是透明四边形，
MSAA 管不到它的 alpha 边缘。交付的 `spirit.png` 一个字没动。

### 她需要一圈描边（2D 版）

近白调子的剪纸站在近白房间里没有边可看：实测晴室里衣料与背景差不到 **35 级**，
而 bloom 与 26% 散焦又把剩下那点吃掉。所以加了一圈：**同一张贴图、填平色、画在她身后、
四边各放大 `RIM_D`**。她自己的不透明像素盖在上面，只留下 alpha 正在衰减的那一圈——
也就是轮廓，而且是**她自己原本的软度**。它同时把她轮廓内部的缝（叶冠之间、发下）也填上，
这是她读起来像"画的"而不是"贴的"的第二个原因。

### 判她有没有在唱：先量这页的钟，再问对对象

`tools/_sing.mjs` 量的是 `window.__spirit` 上的 `bob` / `sing` 两个数字，idle 作对照。

**这两个数字是被一次假读数逼出来的。** 第一版探针量的是她在屏幕上的脚印
（`overSpirit` 射线求交的结果）——她是一块 billboard 的时候，脚印**就是**她的缩放，
这是个忠实的代理量。她变成实体那天这个前提就死了：`overSpirit` 打的是一个**不缩放的隐形胶囊**，
于是第二版探针报出 `her box 75 x 282 px`、而 idle 与 singing 的宽度 range 都只有 **1.0**，
FAIL。坏的不是实现，是**断言的前提**。修法不是换个统计量，是**让页面把数字说出来**：
`window.__spirit` 是一个只读口，页面自己从不读它（`ghost.js` 的 `update` 把 `bob` 同时写在
state 上，`main.js` 把它转出来）。`aimX` / `aimY` / `hover` 后来也挂在这里，给 `_pick.mjs`
验"她看指针的方向对不对"——**符号是最容易在重构里悄悄翻掉的东西**，而翻掉之后静态画面
看不出任何异常。

写它的时候还踩了三个坑，都值得记下来：

1. **无头 Chrome 报 `prefers-reduced-motion: reduce`**，而页面在 load 时读一次就不再变，
   `spirit.update` 于是拿到 `dt = 0`，三条动全冻在静止姿。第一版探针没设
   `Emulation.setEmulatedMedia`，量到 idle 与 singing 的 range 全是 0，报 FAIL。
2. **`dt` 被截到 1/20 s**，而软件渲染下这页只有 0.5 fps —— **她的钟比墙钟慢 40 倍**，
   一次 idle 呼吸是 179 秒墙钟。第一版只跑 2.4 秒，等于看她钟上的 0.06 秒。
   修法是把 `deviceScaleFactor` 降到 **0.35**：布局仍是 1440×900、`innerWidth` 不变，
   但绘制缓冲小到 7 倍帧率（3.5 fps），窗口因此够长。射线拾取不受影响，它映射的是
   `clientX / innerWidth`，不是像素。
3. **开场推轨是一段相机运动，而相机一动她的投影尺寸就变** —— 也就是把被测的那个量动了。
   它只在 URL **完全没有查询串**时播（`main.js`：`prefs.intro && ![...Q.keys()].length`），
   而 `file://` 恰好就是这个形状：dev server 那几次带 `?intro=0&t=…` 从没播过，
   产物那一次一直在播，于是 idle 量到 range **65** 而 dev 是 **12** —— 多出来的全是推轨的尾巴，
   报 FAIL。修法不是等（她的钟 1/40 速，3.4 秒的推轨要几分钟墙钟），
   是**给 URL 补上 `intro=0` 并把这次替换打印出来**：和上面那条媒体特性一样，
   消掉一个变量，而不是指望它自己走完。显式传 `intro=1` 则直接拒绝运行。

改对之后的实测（1440×900，idle 45 s / singing 25 s）：

```
                  idle bob range     singing bob range   ratio
有声              0.150              0.550               3.67x
无音频            0.150              0.550               3.67x
```

这两个绝对值不是统计出来的，是**逐位对得上的**：`update` 里浮沉是
`sin(t·speed)·(0.075 + s·0.20)`，所以 idle 的双峰差正好 `2 × 0.075 = 0.150`、
singing 正好 `2 × 0.275 = 0.550`，比值 `0.275 / 0.075 = 3.67`。**读数与源码公式吻合到第三位**，
这才是这条断言硬的地方——比值只是两个统计量相除，窗口长度一换就会飘。

第二行是**「完全没有音频」那一支**（`SING_PRELUDE` 把 `<audio>` 的 src 换成不存在的文件）：
按下播放后 `playing=true` 而 `audio.paused=true`、`t=0`，页面自己报了 `音频加载失败（4）`，
可她的 `bob` 和有声时**一模一样**。这就是 `sheSings` 与 `musicLive` 分开的全部意义，
也正是「芯片上印着『她只做口型』、她却纹丝不动」那个矛盾的反面。

`_pick.mjs` 另外用**真实输入**验了事件交付那一半
（合成事件测不了它：轨道相机的 `setPointerCapture` 会在监听器里抛 `NotFoundError`，
而 DOM 监听器的异常被浏览器吞掉，于是合成事件会报告一个看起来正常、实际从未执行 capture 的页面）。

## 画面

- **渲染缩放**：DPR 封顶 **1.5×**。2× 屏本身就是 1× 屏的四倍像素，而这套后期链要在上面再叠 4×MSAA 的
  half-float 靶、96 抽样 AO、5 级 bloom 和 27 抽样调色——1.5× 是这种画面（辉光、颗粒、色散、真实散焦）
  看不出和 2× 差别的地方，而且**只有画布缩放**，界面是 DOM，任何像素比下都是清的。
  缓冲不足 **3M 像素**时再叠 **1.25× 超采样**、最后一级缩采样，边缘接近 4×SSAA；1× 的 1080p（2.1M）拿得到，
  2× 的 1080p（3.9M）拿不到。`性能模式` 把封顶降到 1.1× 并关掉超采样与地面镜像。
- **坑：`EffectComposer.setSize()` 会再乘一次它自己的 `_pixelRatio`**，而构造时抓到的是**设备 DPR**、
  不是渲染缩放。把已经乘过 dpr 的 `bw × bh` 传进去等于缩放两次：2× 屏 1080p 实测后处理缓冲到了
  **5326 × 2600 = 13.8M 像素**（4×MSAA、96 抽样 AO、5 级 bloom 全在这个尺寸上跑），帧率就是丢在这里的，
  不是几何。修法是把它的 `_pixelRatio` 钉成 `1`，之后传进去的数字就是真实缓冲——`uTexel` 一直是按
  真实缓冲算的，所以散焦半径在 2× 屏上原本也偏大了 1.5 倍，一并纠正。
- **镜头感**：全屏 pass 里做了距主体越远越糊的 9 抽样散焦（大光圈感）、径向色散、暗角、颗粒，
  加上胶片式分离色调（暗部偏冷/高光偏暖）和最亮高光的暖色溢出（halation，颜色随房间走：
  `uHalTint` 从晴室的暖橙到深潭的冷蓝，`applyTheme()` 每帧 `lerp`）。
- **横向眩光**（`post.js` 的 `Glare`）：亮处被镜头拉成的那道横条。每侧 6 抽头、权重 `1/i`，
  抽头间距 `uStride`、起亮阈值 `uThreshold`、色与强度都挂在房间上（`THEMES[*].glare`）——
  深潭的横条最长最蓝，晴室那套**弱到基本看不出来**（它就该是"亮面上有一丝横纹"）。
  `EffectComposer` 对 `enabled === false` 的 pass 是真跳过，不是把强度设 0，
  所以设置里关掉它是**省下一次全屏纹理采样**，不是只把结果乘零。
- **环境与光**：PMREM 里塞了 7~9 块 HDR 柔光板（主光、冷暖侧条、顶部补光、两颗小 kicker 出锐利高光点），
  环境贴图每帧极慢自转，高光会在壳面上缓缓游走而不是钉死。
- 2048 阴影贴图 + 软 PCF、雾一样的双层尘埃（一层实、一层大颗粒虚焦 bokeh）。
  尘埃飘到顶会回收到底部，两头都按高度淡出，所以看不到粒子"闪一下换个地方"。
- **实时地面镜像**：每帧在主渲染前用镜像相机渲染一次场景到 RT，采样时沿屏幕 Y 做 13 抽样高斯拖影
  （抛光石地板的反射是竖向拉伸的），再叠距离衰减与掠射角增强。没用 three 的 `Reflector` 插件——
  它的 `onBeforeRender` 会在玻璃的透射通道里再次触发，导致渲染器 `setRenderTarget` 重入（实测直接把浏览器窗口搞崩），
  自己算反而干净，还能在低性能设备上一键关掉（降质时先关它）。
- **片头**：磁带一开始**停在地板上**（0.7 秒，够看清它是"放"在那儿的），然后**线性带阻尼**地悬浮到它该在的
  高度——线性走完大部分行程，最后一段交给缓出，所以是"升上来"而不是"被电梯送到"。它不再从地板底下穿上来：
  从下面出来的话，前面两秒整个主体都在往一张它不该穿过的平面里挤，而这是这个场景别的地方都很在意的事。
  镜头同时在 3.4 秒里从更远更低的机位推回默认机位，带盘在上升时还在转。
- **投影接收面**：`ShadowMaterial` 叠在镜像之上（renderOrder 控制次序），影子会连反射一起压暗。
- 主体背后一层暖色辉光墙给虚空补纵深、地板上一圈暖色光池。

调试用：URL 加 `?fps=1` 会在顶部显示实时帧率 / 每帧 JS 耗时 / 当前 dpr / 镜像开关 / 主体横向偏移。


### 取景：镜头一直在看她的脚下

`Orbit` 的 `target` 是上游留下的 `(0, 0.05, 0)`——那时主体是**磁带**，它的中心就在 0 附近。
换成角色之后这个数字没跟着改，而她站在 `FLOOR_Y = −1.62`、身高 6.38，于是镜头一直瞄着地板：
她浮在画面上半部，下面空出一大片地板。2026-10-04 用户："还有很多背景留白"。

两处一起改：

- **`target.y` `0.05 → 1.30`。** `target` 是 `Orbit` 的**全局属性**、不是 `VANTAGES` 的字段
  （`VANTAGES[*].v` 只收 `{theta, phi, radius}` 三个量），所以改一次四个机位一起正过来。
- **`front` 的 `radius` `31 → 23`。** 31 是给"产品机位"定的距离，人像不需要那么多空气。
  纸的宽度由 `--plate-max` 决定、跟镜头距离无关，所以推近不会挤到右侧那张纸。

`detail`（特写）仍是 21，没动。


## 灯光（按摄影棚逻辑布）

`src/lights.js` 里是一套照片级的五灯位，不是"3D 场景灯"：

| 灯位 | 作用 | 实现 |
| --- | --- | --- |
| key | 主光，相机轴 45° 偏左、仰角约 33°，暖色 | `RectAreaLight` 9×6 |
| fill | 副光，反侧、贴近相机轴、大而弱、偏冷 | `RectAreaLight` 12×8 |
| rim | 轮廓光，背后窄条，勾出剪影 | `RectAreaLight` 1.3×13 |
| bounce | 桌面白卡反弹，抬起底部暗部，暖色 | `RectAreaLight` 12×12（低位） |
| top | 顶部大面积补光，保证标签面可读 | `RectAreaLight` 12×12（高位） |
| shadow | 只负责投影（柔光箱不投影） | 与 key 同位的 `DirectionalLight` |

关键点：**`RectAreaLight` 是 three 里唯一像柔光箱的光源**（矩形即发光体，所以光滑壳面上会出现柔光箱本身的矩形高光，
衰减也符合面积光的物理），但它**不能投影**，所以用一盏同方向的平行光专门丢投影。
主光/副光的强度比 ≈ 4:1，色温上主光偏暖、副光与轮廓光偏冷——这是摄影里控制立体感与分离度的基本手段。

背景用一张烘焙好的"无缝背景纸"贴图：竖直渐变 + 主体正后方一团柔和的背景光（真实背景灯打在背景纸上的效果），
其中渐变与地面同色，所以看不到地平线的接缝。切换光环境时，五盏灯的位置、尺寸、色温、强度会一起过渡，
像是灯架被推着换位。

**这张贴图的两处修**（`textures.js` 的 `pool` / `soften`）都是"极点"惹的祸。等距圆柱的一行
就是一条纬线，而极点两侧那两行几乎是零半径的圆——一行里横向的一切都被挤进那个点。背景光是
径向的，横向上有明暗，本来就有东西可挤；而且它比画布还高，在最上最下那两行还剩下四成强度，
正好是挤得最狠的地方。于是极点被捏出一块看得见的糊斑，也就是主体下面那道"渐变的尽头"。
现在这团光画在单独一层里、在到达极点前就被遮罩归零（`POLE_TAPER`）——极点上只剩渐变色，
而渐变是横向均匀的，没有东西可挤；光池的中心和亮度原样留在镜头真正看的那一带。
另一处是**整张图出图前过一道高斯模糊**：分段线性渐变只是 C0，斜率在每个色标处断掉，
在这么大一块面积上就看得见"棱"（三色标的天空会读成三条）；光池自己的衰减边缘、以及
那道遮罩，也都属于斜率突变。模糊是唯一能抹平斜率突变又不挪动形状本身的操作——色标的位置
和颜色、光池的中心和亮度都不动。模糊前先把图按球面的实际重复方式平铺进一张加边的画布
（横向环绕、纵向夹紧），否则模糊会去采样画布外面，极点被拉向透明、u = 0 那条子午线上
还会开一道浅缝。

这套过渡走的是**一条线性时钟**，不是指数衰减。指数衰减前三分之一秒就把大部分行程走完了：往亮里切几乎看不出来，
往暗里切就成了"灯被掐了"——晴室切夜巢就是这么被读成**突然变暗**的。现在灯、曝光、后期、地面色和背景一起按
一条两端缓入缓出的线性进度走 1.6 秒。每个值要走的距离都不一样，所以能共享的不是速率而是**进度**：
对 `dx/dt = rate·(target − x)` 取 `rate = p′/(1 − q)`，解出来正好是 `x = x₀ + (target − x₀)·q`——
所有值都落在同一条 `q(p)` 上，颜色、灯光、透明度因此始终同步。

背景纸是烘焙死的、没有中间态，直接换贴图就是一次硬切——而这是全屏面积最大的一块。所以换环境时是
**第二张球壳把新背景淡上来**（两张都是 `BackSide` + 不写深度，只有绘制顺序说话：不透明的那张先画，
新的透明那张后叠上去），淡完新贴图才提为底图。灯位、曝光、后期参数本来就是缓动，背景跟上之后
整段换环境就没有硬切了，原先那记"快门压暗"因此删掉。

反射探针换环境时会重拍一次。灯的缓动不影响它（探针拍的是灯架那几块面板的几何，而面板在切主题那一刻
就已经是新环境的了），**背景**影响它——所以抓拍的那一瞬间会把背景**临时推到终态**再拍、拍完放回去，
六面立方体是同步渲染的，除了探针没人看得见。这一下本身还是瞬变，没有缓动：PMREM 就是
一张纹理，换纹理是一次赋值，想真的渐变就得把两代 IBL 逐像素混起来，为一步动作上一套乒乓 RT 不划算。
但它现在既不会**当着人**换，磁带也不会在过渡中间变暗：房间变化期间，**磁带手里握的光始终等于此刻房间的亮度**
（`envMapIntensity` 沿着背景自己的交叉溶解曲线走，`(s(t)/s_ref)^2.2`，`s` 是背景在 sRGB 下的平均亮度——
两间屋子交叉本来就是 sRGB 值的 alpha 混合，所以走的就是那个空间）。手里那个探针是旧房间的还是新房间的
都无所谓，强度会把差额补上。

所以换探针那一帧变的不是亮度，而是"反射的是哪间屋子"，那就挑**反射最暗的一帧**换：变暗时是变化的末端，
变亮时当下就是。这样弹的那一下（图案，而非亮度）发生在没人看的时候。抓拍时还会临时把抓力推回 1——否则
探针会把一台"没有环境光"的磁带烤进它自己以后的每一次自反射里。

三套光环境里「晴室」（`studio`）是默认：主副光比 2:1，暖白背景，用来核对材质与印刷。
「夜巢」（`noir`）是唯一一间真正暗下来的厅——主光收窄、环境光压掉，只留一盏金色射灯打在黑墙上。
「深潭」（`abyss`）是同一套五灯位，但**每一盏都带上北向天光的颜色**：没有一盏是暖的，
补光又大又亮（一个天光展厅会把四面墙都反一遍），投影是三者里最轻的。
晴室与深潭都是白房子，差别只在**光的色温**——这也正是为什么"蓝色主题"不是给白天场景
加一层滤镜：那个厅的灯本来就长那样。

> 三个名字都是**按钮上印的**；代码里一律用 `studio` / `noir` / `abyss`。括号里那两个是

> 一改就断一串，所以换脸时一个字没动。

## 环境光遮蔽与自反射

**AO（`src/ao.js`）**：自己写的屏幕空间遮蔽，**全分辨率 + 双尺度 + 双边滤波**：

- 一个 tap 预算里跑两个半径——**近半径 0.17**（螺钉沉孔、磁带缝这种贴合的暗角）和
  **远半径 0.85**（窗口、轮毂开口里的大块遮蔽），各自有独立强度与偏置
- 去噪用**可分离的双边滤波**（横向 + 纵向各 9 tap，按视空间深度差加权），
  所以噪点被抹掉而遮蔽不会糊过轮廓——廉价 SSAO 那种"整体蒙灰"就是这么来的
- 每像素旋转是**固定**的（随时间变化会拿色带换时间性噪点，表现为折缝上的高频闪烁）
- 末端一个**时间累积 pass**：拿上一帧的相机矩阵把当前像素重投影回上一帧，深度校验后混合，
  并钳制在当前帧 3×3 邻域内

整套加起来约 6 个全屏 pass，GPU 上大约 1 ms 级——这台机器上 GPU 本来就在闲着。


**自反射与物体间反射（`src/probe.js`）**：一颗 512² 的反射探针。
把柔光板做成**真实几何但只挂在 layer 2**（主相机和镜像相机都看不到），探针相机额外开启该层，
于是探针一次就同时拍到"灯架 + 磁带自己 + 地面"，经 PMREM 滤波后作为所有机身材质的 `envMap` ——
镀铬导带柱、金属屏蔽片、烟灰玻璃、高光壳面因此会映出相邻零件，而不只是环境。
探针放在壳体左上前方（物体外部），翻面/拆解/换主题后自动重拍。

没有用 SSR：three 的 `SSRPass` 每帧会重渲染两遍场景（自身 beauty + 法线），正好把性能优化抵消掉；
探针方案的代价是视差近似（方向准确、位置是单点采样），但对这种尺度已经够用。

## AO 高频闪烁的成因

三个都是从「遮蔽在每条边上抖」这件事上查出来的，修法都在 `src/ao.js` 与 `src/post.js`：

1. **合成器的深度纹理每两帧才更新一次。** `EffectComposer` 把传入的 render target 克隆一份当读写缓冲，
   而 three 的 `WebGLRenderTarget.copy()` **连深度贴图一起克隆**（`three.core.js`）。`RenderPass` 画进哪个
   缓冲由 `readBuffer` 决定，而这条 pass 链每帧 swap 次数是 3（AO / Output / Grade，奇数），所以
   `readBuffer` 每帧在两张 RT 之间来回切——偶数帧 AO 采到当帧深度，奇数帧采到的却是上一帧的。
   主体每帧只漂 0.08 px，于是遮蔽图案以半帧率在「正确」和「滞后一帧」两张图之间反复横跳，
   每条边都在抖。修法：让两张 RT **共用同一张深度纹理**（`post.js` 一行）。
2. **法线来自 `dFdx/dFdy`。** 深度贴图是 MSAA **resolve** 出来的（`blitFramebuffer(..., NEAREST)`，
   每像素只取一个采样），轮廓处邻像素会在「物体」和「背景」之间跳。一个邻像素跳了，重建出的
   空间位置落到远平面，`cross(dFdx, dFdy)` 跟着翻，整片 2×2 quad 的半球基向量一起歪 → 遮蔽量整体跳。
   修法：邻域 tap 与中心深度差超阈值就**收敛到中心**，跳变变成空操作。
3. **遮蔽判定是阶跃。** `diff > bias ? 1.0 : 0.0`——任何深度变化，哪怕是远小于一个像素的漂移，
   都能让一个采样点从「完全遮蔽」翻到「完全不遮蔽」。改成两端都平滑的 ramp。
   以上两条都消不掉**轮廓本身**的锯齿（它就是一个像素一个像素地跳），所以末端再加时间累积：
   重投影 + 深度校验 + 邻域钳制，既压掉跳变又不会在拆解、走带这些真实变化上拖影。

## 关于“材质正确”的几处实现

> **这一节和下面「水墨晕染」讲的是那台磁带本身，而它现在不在画面上**（`TAPE_ON = false`）。
> 代码逐字有效、每一帧都在跑，只是没人看得见——所以留着它：它是这套材质唯一的书面记录，
> 而且 `TAPE_ON` 拨回 true 的代价是零。想看她，看上面「换脸」那一节。

- **外壳**：烟灰聚碳酸酯 = 低粗糙度 + clearcoat；侧壁用另一套更粗糙的模具面材质，
  叠程序化法线图模拟细皮纹，接缝处刻意留 0.03 的台阶（真实双片壳体就是这样合的）。
- **边**：能看见的直角都留了倒角，且整套几何走**自动平滑着色**。
  倒角是几何而不是着色技巧：挤压件用 `bevelSize`（上下壳 0.03、模具前框 0.022、
  角件 0.018），圆柱件的端面倒角则用 `latheCyl()` 车出来——`CylinderGeometry` 的
  端面与侧壁是真正的 90°，而真正的 90° 边**不产生任何高光**，看上去像纸板。
  轮毂干脆改成一条闭合剖面回转（`hubShell()`）：外壁、轴孔、上下两个端环和四道倒角
  是一个曲面，不再需要"三块拼起来 + 把轴孔翻面"。
  着色侧：`ExtrudeGeometry` 交回来的是平直着色的三角形（它自己对非索引缓冲做
  `computeVertexNormals`，只能得到面法线），于是所有圆角都在按段折线走、倒角是一条棱。
  现在统一过 `toCreasedNormals(g, 35°)`（`autoSmooth()`）：比 35° 浅的棱两侧法线合并、
  比它陡的保持硬边——90° 的真角还是角，rrect 的圆弧（每段 9°）和倒角自己（30°）
  则滚成一条高光。代价可忽略：最大的那块壳板 6048 顶点，5 ms。
- **观察窗**：烟灰玻璃用「透明 + 清漆」而不是 `transmission`。真折射会让 three 把不透明物体
  再渲染进一张单独 RT（每帧多一整遍场景），而 0.055 的厚度下折射本来就看不出来——观感几乎一致，代价差一整遍。
- **磁带**：γ-Fe₂O₃ 磁层用 sheen 表现绒面反光。带条的截面方向是关键——**3.81 mm 的宽度永远沿机身
  厚度方向（Y 轴）竖直**，沿轨迹法线方向的才是厚度，这样磁层面才会正对磁头开口；写反会变成一条
  平躺的板子（顶面朝上反光）。
  厚度就是 `DIM.tTape`（0.3 mm）——**模型里"一层带子"只有一个厚度**：带条是这么厚，走带每转一圈
  带盘半径涨这么多，带盘顶面一圈层纹也是这么宽（真机磁带 12 µm，模型是它的 25 倍；不放大就看不见
  带盘在缩）。几何的 v 分带（`RIB_EDGE`）和两张贴图的分带都从这一个数推出来，所以它们不可能对不上。
  **带盘最外圈就是这条带子本身**：走带的带条在每个带盘上绕**整整一圈**（不是象征性的 1.25 rad），
  因为一圈恰好就是最外层那一层磁带。于是从自由段出来的带子和盘上的带子是**同一条**——同一材质、
  同一张贴图、同一条 uv——接缝处本来就无从割裂。盘体（外筒 + 上下两个圆面）因此比"盘的半径"小
  **一个层厚**：最外层由带条画，盘体画的是它下面那些层（顶面的层纹数也跟着少一层），两者正好齐平。
  带条走在**表面上**而不是穿过它：在盘上它的内表面贴在盘的半径上（中心线在半径内侧半个层厚），
  在导带柱上它的内表面贴在柱面上（中心线在外侧半个层厚）——两个偏移都是同一个 `HT`，所以"盘→柱"
  的切线仍然是对带条本身的切线。
  外筒的材质仍然跟着磁带走（`M.tape` 的克隆），但它现在被带条整个盖住，只在**引带经过时**透出来
  ——那时候你看到的正是它本该是的东西：底下那一层。
  带盘顶面是各层切边的堆叠，配色与光泽跟着切边带走（`tapeEdgeTexture` 的环就是 `rgb(104,88,72)`）。
- **金属**：拉丝粗糙度贴图 + `anisotropy`，螺钉为沉头十字槽。
- **纸张**：纸标有噪点法线、sheen、轻微 clearcoat（覆膜感），低环境反射。标面本身是
  一张水彩，但**不是画上去的，是算出来的**：见下面「水墨晕染」。两面共用一个纸纹场，
  但各走各的显影：A 面三遍 glaze 正片叠底到纸白上，B 面是同一张画滤色到深底上——
  深底靠发光被读、浅纸靠明度被读。B 面仍走旧的 `dissolve()`（轮廓团 + 噪声取阈值），
  它要的正是那种「糊成一片光」的效果。

  还有一条构图上的要点：贴纸被观察到的不是整张纸，而是**窗口镂空之后剩下的边框**（左右两条
  窄边 + 上下两条带）。所以颜料要**在可见边框内侧最浓、到窗口切边前就淡掉**；画在纸中央的
  团块会被裁掉大半，剩下的一点落在角上像块污渍，切口还留下一条直边。标题用 Gabriola 手写体，
  铜色横带已换成手画的墨线。
- **走带**：恒定线速度 4.76 cm/s，两带盘角速度 ω = v/r，带面积守恒（`A_L + A_R = const`），
  磁带包角与切点每帧按外切线解析求解后重建带条几何。
  **带条的 u 走的是弧长，不是采样序号**：14 步横过磁头那段是 3.5 cm，同样 14 步绕过 ⌀1.7 mm 的
  导带柱只有 0.5 mm，按序号铺贴图，涂层的颗粒在两者之间被拉伸 60 倍。改成弧长之后一个 tile 就是
  0.20 cm 磁带（这是原来 60 个 tile 铺满全程的密度，路径弧长只有 12 cm 上下），于是整条带的"走动"落在 `offset.x` 上**一个数**：每帧算出已经跑过磁头多少厘米
  （`s0 = (A_TOTAL - areaL) / 层厚`），四个 texture offset 跟着走——不重建几何、不上传缓冲，
  而且和带盘用的是同一个位置，涂层和轮毂不可能各走各的。
- **引带**：真机磁带两端各接一段未涂布的引带，一面放完时你看见的就是它从磁头前滑过去。这里做成
  **一条 alpha**（`leaderAlpha()` 配 `alphaMap`）：两端各 1% 的带长（按画出来的速度约三秒）留 0.18
  的透明度、两条切边（`RIB_EDGE`，就是 `D.tTape` 那一层）留 0.62，所以"涂层到此为止"是**看进去**的而不是画上去的，切边还在，
  带条不会读成缺口。它必须挂在**磁带自己的坐标**上——挂在带条的 u 上会被每 20 cm 重复一次——所以
  带条有两个 uv 通道：`uv` 是路径弧长（涂层，tile 单位），`uv1` 是磁带自己的厘米坐标（引带），
  后者只在重建路径时写，之后靠 `alphaMap.offset` 滑。材料因此变成 `transparent: true`，但**仍然写
  depth**：AO 读深度缓冲，磁带写深度它才不至于被当成背景。引带看不见比遮蔽断掉更可接受。
  画出来的引带比真机长得多（真机 15 cm 对 194 m，这里 1%），因为按真比例它在任何一个时刻都看不见。
  快倒 `REW_SECONDS = 8.5`：真机倒回一面约是播放时间的四十分之一（这一面 5:17 → 八秒半），
  4.2 秒时盘缘一秒转十圈、快倒末尾五十圈，是糊，不是倒带。
- **轮毂转动**：六个齿朝向中心孔内伸（外径 12 mm、内孔 ⌀7 mm 的真实比例），从上方能直接看到齿在转；
  带盘顶面额外画了一道极淡的螺旋接缝和卷带末端台阶，打破旋转对称，让带盘自身的转动也看得出来
  （螺旋特意画成十二圈：`alignPack` 只会用到这张盘最里面那一小圈，外圈的转数会被缩放到画面之外）。
  转速由 `ω = -(dA/dt)/(层厚·r)` 反推，所以播放、快倒、外部音频驱动三种来源都自动正确。
- **带盘的两个面按半径重新参数化**（`alignPack`，只在半径动了看得见的一点点时才写，60 fps 下
  每帧漂 3.5e-5）：顶面那张层纹贴图绕盘心**径向缩放**，让层间距恒等于 `D.tTape`——满盘七十多圈、
  快空时两三圈，而间距始终是 0.3 mm（盘体比盘的半径小一层，所以圈数也正好是它下面那些层的数目）；
  侧面的 u 换成**整数个 `D.tile` tile 绕周长**（取整所以接缝仍然接得上，跳一个整 tile 也看不出来）。
  侧面的三张贴图是磁带那三张的**副本**而不是同一份：带条的涂层会沿着带走（`alignTape` 每帧写
  `offset.x`），而带盘的外圈不会滑、只会跟着盘转。
- **色彩**：Linear 工作空间 + Neutral tone mapping + 线性 HDR bloom，颗粒/暗角在色调映射之后叠加。

## 水墨晕染（A 面那张水彩是怎么来的）

先说为什么不能"画"：把一片水彩画成一个**有柔边的形状**，得到的是喷枪——一个均匀的色调、
一条均匀的衰减、一个因为画得圆所以圆的外轮廓。水彩不是形状，是**水在纸里走，颜料留在水停下的地方**。
所以不是画，是模拟：`src/textures.js` 里 448×276 的小格子上跑一遍，画出来的东西只是这次流动的记录。

五条规则，每条都很便宜：

1. **纸有三层尺度**。`perm` 是这一格多能吸水，`fib` 是两组正交拉伸的噪声、代表纤维走向，
   `fine` 是纸纹。于是轮廓在三个尺度上**同步地**毛起来——那些须是跟着场走的。
   这一点是「噪声过阈值」永远做不到的：那里的毛是逐像素的，看着像脏，不像纸。
2. **会冻住的湿边**。一格只要有压强（`wi·give`）压过纸的阻力，就把水递给外面一格；
   能不能过这一格由纸纹决定，而压强只减不增（蒸发）。于是边界像潮线一样各自停在不同的时刻。
3. **颜料跟着水走**（donor-cell upwind）。光这一条就会把颜料堆到边上，加上"干掉的那格把
   还攥着的一把颜料扔下"，深色的**水痕**就自己出来了——不是画出来的。
4. **沉积与重新溶解**。水膜变薄，颜料析出；后来再有水到，又把它拎起来。于是**在快干的洗色上
   滴一滴清水**，它会把颜料拎起来往外推，形成中间浅、四周有丝的开花——就是一般人说的"晕染"，
   渐变是拿不到这个的。
5. **两种颜料**。水彩会分层：重的颗粒留在原地，轻的跟着水走得更远、干了以后是一圈更宽的冷调
   光晕。同一个水里带两种，一片洗色才有"芯 + 晕"，而不是一个平调子。

一遍 glaze 跑完是 400 ms 上下，A 面三遍（蓝灰场、青调、暖调）≈ 0.7 s，只算一次。
改浓度看 `DAY_LOAD` / `DAY_DENSITY`，改构图看 `DAY_GLAZES` 里那几笔（都是纸面比例）。
调试时可以用 `tools/wash-preview.mjs`——同样的算法在 Node 里跑，直接把结果写成 PNG，不用开浏览器。
（这一节讲的这张水彩现在贴在**那台看不见的磁带**的纸标上，见「换脸」。）

## 设置

页头 **设置**（或 `,`）打开一张设置页——用的就是总目录那套浮层，一行一件事：

| 开关 | 它接的是页面里本来就有的什么 |
| --- | --- |
| **开场动画** | 打开时那 3.4 秒的推轨与浮起（= `?intro=0`）。**下次打开生效**，它只在启动时读一次 |
| **循环播放** | 放完自动倒带重放（`ended` → 倒带 → 再放）。关掉的话**照样倒回开头**，只是倒完停在那儿，计数器回 `00:00`，按钮回到「演唱」 |
| **房间底噪** | 唱歌时的嘶声与低鸣（`bedLevel()`）。换向声、旋钮声不受影响，它们走的是另一条母线 |
| **按键提示** | 底部那排快捷键键帽（`body.keys-off` 把 `.hud-c` 收起来） |
| **地面镜像** | 地面那遍实时反射（`floorBase`）。关掉能省一整遍场景渲染——性能守护程序本来也会先砍它，这个开关是同一件事的手动版，两者取「与」 |
| **音频联动** | 演唱时频谱柱、浮尘速度与辉光跟随音乐（`src/viz.js`）。数据来自合成时就算好的四段包络；自己装的歌走一个 `AnalyserNode`。**`file://` 下 `createMediaElementSource` 会被浏览器拒绝**，所以本地双击打开时自己装的歌退回原来那套关键帧动画——柱条照样动，只是不跟音乐。演示曲不受影响，它的包络是离线算的。**关掉不影响声音，也不影响她唱**——她看的是走带台在不在转，不是频谱柱在不在动（见「换脸」） |
| **性能模式** | 渲染分辨率 1.5× → 1.1×，并关掉超采样与地面反射。这一页里唯一一个**直接改 GPU 负载**的开关：打开会重跑一次 `onResize()`（那才是真正重建缓冲的路径），然后把镜像也收走——`mirrorOn()` 要求它关着，所以它和「地面镜像」是「与」不是覆盖。音频联动也一并收走，`vizOn()` 是同样的写法 |
| **镜头眩光** | 亮处那道横向光条（后期链里的 `Glare`，见「画面」）。三套房间各留自己的色与长短，晴室那套本来就弱。**故意不挂性能模式**：它是一个 pass，但它想说的是"这间屋子的镜头长什么样"，跟分辨率无关，所以 `glareOn()` 只看它自己 |
| **暗角** | 画面四周压暗的那一层（后期链里的 `uVig`），这一页里**唯一一条滑条**：0–100%，**默认 50%**（它最早是开关，默认关；改成滑条后默认 0，再调到 50%）。滑条乘的是各房间**自己**的深浅（`applyTheme()` 里 `(G.vig ?? 0.85) * prefs.vig`），两个房间现在都是 0.85，各自留自己的比例。目标值走的是 `damp()`，所以拖的时候画面跟手但慢半拍，归零是淡出而不是瞬间消失；每 5% 一档，过档响一声和总目录同款定位声 |

开关记在 `localStorage`（键 `ohmtape.prefs` —— 键名是历史遗留，没跟着换脸一起改：改了就
等于把所有老访客的设置重置一遍；读写都裹了 try/catch，存储被禁用就退回默认值）。
存下来的对象里带一个 `v`（`PREF_V`），是**这套默认值的版本**：存下来的值优先于新默认值，所以改默认值对"用过这页的人"反而是看不见的
——`vig` 的默认就是从 0 改到 50% 的，凡是碰过任何一个开关的浏览器手里都攥着那个 0。所以**上一代的 `vig` 不读回来**（只这一次），
其余开关照旧是访客自己的设置。下次再动默认值，把 `PREF_V` 加一，并在同一个 `if` 里点名那个键即可。
**只有设置会跨刷新保留**——音乐是故意不保留的（见「音乐」）。

## 重新打包

```bat
重建.bat
```
（等价于 `node build.mjs`，需要 Node.js；脚本会临时把 `C:\Program Files\nodejs` 加进 PATH。）

**改过 CSS、或改了任何会被内联的东西之后，还要再跑一步：**

```
node tools/standalone.mjs
```

两步的分工是：`build.mjs` 出 `dist/app.js`（页面用 `<script src>` 引用它）；
`standalone.mjs` 把 `index.html` 里引到的一切（样式表 + `dist/app.js`）内联进
`dist/ghost-standalone.html` —— 那才是能双击打开、能丢进任何静态托管的交付物。
**只跑第一步的话，交付物还是旧的**，而且不会报错，只会静默地少改一样东西。

她现在是**纯程序化**的，所以这一步报「内联 2 个外部资源」、产物里
`grep -c 'data:image'` 是 **0** —— 这是**正常**的，不是回归。规则本身与角色无关，
所以脚本留着（哪天要加回一张贴图，它得在）。

> **探针要连对本项目的浏览器。** 这些脚本的默认 CDP 口是 **9445**，但 9445 在本机被另一个
> 项目占着——`tools/_dev.mjs` 给这个仓库起的是 **9447**（http 口 8932）：
> `node tools/_dev.mjs . 8932 9447`。**连错端口会拿到别人的页面**，而截图看起来完全正常，
> 只是画的是别的东西；`page-shot.mjs` 还要额外设 `CDP_PORT=9447`（它的默认值是 9445）。
> 所以下面每条命令都显式带上端口。
>
> ★ 这两个数是**启动时给的参数，不是常量**：`_dev.mjs` 每次都照你传的来，端口被占就换一个。
> 下面写的 8932 / 9447 是最近一次用的，**跑之前先确认自己起在哪个口**——照抄一个已经死掉的
> 端口，报的错是 `ECONNREFUSED`，而照抄一个活着的、但不是这个项目的端口，报的错什么都没有。

产物是不是真自足，一条命令验：

```
node tools/_eval.mjs "file:///<绝对路径>/dist/ghost-standalone.html" "@tools/_smoke.js" 9447
```

`externalRefs` **必须是空数组** —— 非空就说明还有东西在指向旁边的文件，而那个文件在别人的机器上不存在。
它同时报：loader 落没落、WebGL 上下文丢没丢、标题 / 品牌 / 主题按钮是不是她那一套、
右侧纸面的正文与五条动作、磁带那两个按钮的节点数是不是 **0**、位图节点（`img` 与非 `#gl` 的 `canvas`）
是不是 **0**、以及 `window.__spirit` 那个只读口是不是 `live`。前一条要的是 0 而不是「看不见」：
藏起来的节点仍然可聚焦、仍然会被读屏念出来，所以 `TAPE_ON` 关的是**标记本身**，不是它的样式；
后一条要的也是 0，因为她是用图元搭出来的，出现一张解码好的位图就意味着某个旧资产又回来了。
（产物里唯一剩下的裸 `assets/` 是 `assets/sacred-play-secret-place.mp3`，那是 `TRACK_DEFAULT` 里的
占位常量 —— `boot()` 在任何人读它之前就换成了演示带自己的 A 面，所以它从不被请求。）

产物**不能**只靠「文件在、体积对」来判，也不能靠一张截图看着对——她本人有没有真的在唱，
得量数才算数：

```
node tools/_sing.mjs "file:///<绝对路径>/dist/ghost-standalone.html" 9447 0.35 45 25
```

判据是三条独立的断言（press 前不唱 / press 后唱 / 因此动得更多），
量的是 `window.__spirit` 上那两个只读数字，不是屏幕上的任何东西 —— 理由见「换脸 · 判她有没有在唱」。
产物上跑出来的读数应该与 dev server **一致**：`bob` 的 range 是 `0.150` 与 `0.550`，
两个数与源码里的幅度常量（`0.075` / `0.275`）逐位吻合。

**判"描边在不在"要量像素，不要看截图。** `tools/_px.mjs` 干的就是这件事
（自带一个 60 行的 PNG 解码器，因为运行时的两个依赖都不解图）：

```
node tools/_px.mjs "http://127.0.0.1:8932/index.html?intro=0&t=studio&v=front" "420,235,280,30" 14 9447
```

它把一条扫描线打成亮度，再打成三通道。描边该有的形状是「墙 → 一个**下凹** → 她的轮廓」：
最小值如果落在她的**边缘**而不是她的身体上，这条边就是真的。
